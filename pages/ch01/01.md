<div class="unit">L01-U03 · 三问表 / 前半段</div>

# 先问：请求有没有发出、有没有连上？

| 环节 | 谁负责 | 常见失败 | 去哪里看 |
|---|---|---|---|
| 浏览器构造请求 | 前端代码 / 表单 | 没发出、方法或 URL 错 | **Network 先确认请求存在** |
| 解析与连接 | OS / 网络 / DNS / 证书 | 域名解析失败、拒绝连接、TLS 错误 | Network 失败详情、`curl -v` |
| 反向代理 | Nginx 等 | 502 / 504、代理侧 404 | 代理访问与错误日志 |
| ASGI 服务器 | uvicorn | 端口未监听、进程退出、启动失败 | **启动终端输出** |

<div class="note">适用范围：本课程开发环境的常见情况。生产环境还可能有 CDN、负载均衡与容器编排。</div>

<div class="unit">L01-U03 · 三问表 / 后半段</div>

# 请求进入服务端以后，在哪留下迹象？

| 环节 | 谁负责 | 常见失败 | 去哪观察 |
|---|---|---|---|
| 中间件链 | 框架与自定义中间件 | 拦截请求、漏响应头 | **② 应用日志** |
| 路由与参数解析 | FastAPI | 路径不匹配 404、参数不合法 422 | 响应体与 `/docs` |
| 应用代码 | 你写的端点 | 500、业务逻辑错但返回 200 | **② 日志＋③ 断点栈帧** |
| 数据库 | PostgreSQL / 本地备用 SQLite | 连接失败、SQL 错、查询慢 | **④ SQL 调用日志** |

<div v-click="1" class="callout">“哪里可能坏”只是猜测；<b class="key">“在哪观察”</b>才把猜测变成排查动作。</div>

# 请求的四部分：一行、一组头、空行、体

<div class="cols-code">
<div>

```http {1|2-4|all}

Host: 127.0.0.1:8000
Accept: application/json
Content-Length: 0

```

<div class="source">结构示意，非抓包原文；此请求的请求体为空。</div>
</div>
<div>

<ol class="message-parts">
<li><b class="key">请求行</b>：方法、请求目标、协议版本。</li>
<li v-click="1"><b class="key">请求头</b>：描述目标、内容、协商等。</li>
<li v-click="2"><b class="key">空行</b>：结束头部。</li>

</ol>

<div class="unit">L01-U09 · 状态码与自动化工具 / 适用条件</div>

# 状态码是给机器看的信号

| 谁在读状态码 | 错误包装成 200 的具体后果 | 必要前提 |
|---|---|---|
| 监控与告警 | 状态码错误率低估，真实业务失败可能漏报 | 告警只按状态码统计 |
| 缓存 / CDN | 错误内容可能按“成功响应”策略保存和分发 | 方法、缓存头与配置允许缓存 |
| 代理 / 负载均衡 | 健康判断或故障转移失真 | 相应策略依赖状态码 |
| 客户端重试 | 不进入预期的失败分支 | 重试策略只识别状态码 |

<div v-click="1" class="callout">这些工具通常<span class="caution">不会替你的应用解析</span> <code>success</code> 字段。把失败语义只藏在私有响应体里，就切断了通用信号。</div>

# 新 API 有路标，不要求凭空写出

<div class="cols wrap-code">
<div>

```python
from fastapi import Path as PathParam
from fastapi.responses import JSONResponse
from sqlalchemy.exc import SQLAlchemyError
```

<p><b class="key">参数约束</b>：签名中用 <code>qid: int = PathParam(ge=1)</code>；HTTP 输入由框架校验，不是 Python 注解自行强制。</p>
<p><b class="caution">别名原因</b>：模板已有 pathlib.Path 用于静态文件路径，不能被同名导入覆盖。</p>
</div>
<div>
<p><b class="key">显式返回状态</b>：<code>JSONResponse(status_code=404, content=payload)</code>；payload 按前页规格构造，不只返回 success=False。</p>
<p><b class="error">捕获数据库故障</b>：把获取连接与执行 SELECT 1 都放进 try，使用 <code>except SQLAlchemyError</code> 返回规定的 503。</p>
<p><b class="example">相关语法</b>：with 管资源；try/except 改变执行路径；return 返回响应对象。</p>
</div>
</div>

<div class="note">这是 API 用法提示，不是完整实现。查阅：<a href="https://fastapi.tiangolo.com/tutorial/path-params-numeric-validations/">路径约束</a> · <a href="https://fastapi.tiangolo.com/advanced/response-directly/">直接返回响应</a> · <a href="https://docs.sqlalchemy.org/en/20/core/exceptions.html#sqlalchemy.exc.SQLAlchemyError">SQLAlchemy 异常</a>。</div>

# 示例的三个阶段与启动方式

| 阶段 | 用途 | 启动模块 |
|---|---|---|
| v1-ai-raw | 可运行反例 | `v1_ai_raw:app` |
| v2-traceable | 可追踪版本；plain / trace 可切换 | `v2_traceable:app` |
| v3-m0 | 练习参考，课后发布 | `v3_m0:app` |

```bash
# 先在终端进入 snippets/ch01/m0-tracer 目录
uv sync --frozen
uv run python seed.py
uv run uvicorn v1_ai_raw:app --host 127.0.0.1 --port 8000
```

<div class="note">Python 3.12；实际依赖锁在 uv.lock。初始数据：30 questions＋15 answers＋5 tags，均为虚构。仅限本地演示。</div>
