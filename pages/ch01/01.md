<div class="unit">L01-U03 · 三问表 / 前半段</div>

# 先问：请求有没有发出、有没有连上？

| 环节 | 谁负责 | 常见失败 | 去哪里看 |
|---|---|---|---|
| 浏览器构造请求 | 前端代码 / 表单 | 没发出、方法或 URL 错 | **Network 先确认请求存在** |
| 解析与连接 | OS / 网络 / DNS / 证书 | 域名解析失败、拒绝连接、TLS 错误 | Network 失败详情、`curl -v` |
| 反向代理 | Nginx 等 | 502 / 504、代理侧 404 | 代理访问与错误日志 |
| ASGI 服务器 | uvicorn | 端口未监听、进程退出、启动失败 | **启动终端输出** |

<div class="note">适用范围：本课程开发环境的常见情况。生产环境还可能有 CDN、负载均衡与容器编排。</div>

<!--
教学单元：L01-U03；本页：三问表前半。

-->

<div class="unit">L01-U03 · 三问表 / 后半段</div>

# 请求进入服务端以后，在哪留下迹象？

| 环节 | 谁负责 | 常见失败 | 去哪里看 |
|---|---|---|---|
| 中间件链 | 框架与自定义中间件 | 拦截请求、漏响应头 | **② 应用日志** |
| 路由与参数解析 | FastAPI | 路径不匹配 404、参数不合法 422 | 响应体与 `/docs` |
| 应用代码 | 你写的端点 | 500、业务逻辑错但返回 200 | **② 日志＋③ 断点栈帧** |
| 数据库 | PostgreSQL / 本地备用 SQLite | 连接失败、SQL 错、查询慢 | **④ SQL 调用日志** |

<div class="callout">“哪里可能坏”只是猜测空间；“在哪观察”才把猜测变成排查动作。</div>

<div class="unit">L01-U04 · 请求结构 / HTTP/1.1 文本示意</div>

# 请求的四部分：一行、一组头、空行、体

<div class="cols-code">
<div>

```http
POST /getQuestions?keyword=react HTTP/1.1
Host: 127.0.0.1:8000
Accept: application/json
Content-Length: 0

```

<div class="source">结构示意，非抓包原文；此请求的请求体为空。</div>
</div>
<div>

1. **请求行**：方法、请求目标、协议版本。
2. **请求头**：描述目标、内容、协商等。
3. **空行**：结束头部。
4. **请求体**：本例没有内容。

</div>
</div>

<div class="callout">POST 不等于“参数一定在 body”。此函数的简单参数来自查询串，查看 Query String Parameters。</div>
<div class="note">HTTP/2、HTTP/3 用帧与伪头表达，不是这份文本排版；协议语义下次展开。</div>

<div class="unit">L01-U04 · 响应结构 / HTTP/1.1 文本示意</div>

# 状态、元数据、内容，是三种不同的事实

<div class="cols">
<div>

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"success": true, "data": [...]}
```

<div class="source">省略其他响应头与数据；结构示意，不是完整实际报文。</div>
</div>
<div>

1. **状态行**：版本、状态码、原因短语。
2. **响应头**：如内容类型。
3. **空行**：结束头部。
4. **响应体**：本例是 JSON。

</div>
</div>

<div class="callout">Headers 看 HTTP 状态与响应头；Response 看服务端返回的内容。不要把页面上的提示当作原始响应。</div>
<div class="note">今天识别结构；第 2 次课讨论方法、状态码和缓存的完整语义。</div>

# 给一次请求的所有记录，打同一个标记

<div class="hero text-center"><code>request-id</code></div>

<div class="thirds">
<div class="panel"><h3>进入时确定</h3><p>合法的调用方 id 优先；没有则生成随机标识。</p></div>
<div class="panel"><h3>内部传递</h3><p>保存到 <code>request.state</code>，端点读取后打日志。</p></div>
<div class="panel"><h3>响应时带回</h3><p>写入 <code>X-Request-ID</code>，用户报障时能提供它。</p></div>
</div>

<div class="unit">L01-U09 · 四个具体后果 / 条件写在一起</div>

# 状态码是给机器看的信号

| 谁在读状态码 | 错误包装成 200 的具体后果 | 必要前提 |
|---|---|---|
| 监控与告警 | 状态码错误率低估，真实业务失败可能漏报 | 告警只按状态码统计 |
| 缓存 / CDN | 错误内容可能按“成功响应”策略保存和分发 | 方法、缓存头与配置允许缓存 |
| 代理 / 负载均衡 | 健康判断或故障转移失真 | 相应策略依赖状态码 |
| 客户端重试 | 不进入预期的失败分支 | 重试策略只识别状态码 |

<div class="callout">这些工具通常不会替你的应用解析 <code>success</code> 字段。把失败语义只藏在私有响应体里，就切断了通用信号。</div>

<!--
教学单元：L01-U09；本页：用后果说明规则。
不宣称任何 200 都会缓存或任何 5xx 都会摘除实例。健康检查、代理重试、缓存都有配置边界。不能据此把正常的空搜索结果当 404；空列表也可能是成功响应。
-->

# “我自己判断 success”为什么还不够？

<div class="cols mt-8">
<div class="panel"><h3>浏览器的列表筛选</h3><p>按状态码筛失败时，这些请求仍表现为 200。</p><p>DevTools 的颜色因版本而异，不能只看“是不是绿色”。</p></div>

</div>

<div class="callout">让状态码表达适当的 HTTP 结果，响应体补充业务细节；前端仍应检查状态并展示可理解的错误。</div>

# 重试前，先理解失败，再考虑副作用

| 类别 | 先怎样理解 | 下一步 |
|---|---|---|
| **2xx** | 服务端按 HTTP 语义报告成功 | 仍要检查业务结果是否符合规格 |
| **4xx** | 请求条件、权限、资源等有问题 | 多数需改请求；不要盲目原样重放 |
| **5xx** | 服务端未能完成请求 | 可能暂时性，也可能永久性故障 |

<div><h3>本例是普通查询</h3><ul><li>GET 的 URL 可直接打开、收藏与分享。</li><li>更自然地使用浏览器和中间缓存的常见策略。</li><li>安全、幂等语义给预取与重试提供依据。</li><li>日志中的方法帮助判断意图，但不能证明实现没有副作用。</li></ul></div>
<div class="panel"><h3>POST 查询是有意识的例外</h3><p>条件很长，或不希望条件出现在 URL 历史与访问日志中，可以设计 POST 查询。</p><p>要说明理由与缓存、重试策略；POST 本身不加密内容，也不保证正文不被记录。</p></div>
</div>

<div class="callout">POST 并非协议上绝对不能缓存，但通用缓存支持有限。不能把 GET 的安全语义默认套给 POST。</div>

# `GET /questions/{qid}`

<div class="cols">
<div>

**路径参数**：`qid` 为整数，且 ≥ 1。

**200 成功**：

```json
{
  "id": 1,
  "title": "...",
  "body": "...",
  "created_at": "..."
}
```

</div>
<div>

**404 不存在**：

```json
{
  "code": "question_not_found",
  "message": "...",
  "request_id": "..."
}
```

**422 参数不合法**：`abc`、`0`、`-1`。由框架校验产生；本次不要求定制其响应体。

</div>
</div>

<div class="callout">包括 404 / 422：响应头有 X-Request-ID；传入合法 id 要沿用；日志有同一 rid 的进入与离开。</div>

# GET /healthz：让机器知道该不该接流量

<div class="cols mt-6">
<div class="panel"><h3>数据库可用 → 200</h3><p><code>{"status":"ok","db":"ok"}</code></p><p>只执行 <code>SELECT 1</code>，不查询业务表。</p></div>
<div class="panel"><h3>数据库不可用 → 503</h3><p><code>{"status":"degraded","db":"down"}</code></p><p>捕获数据库操作异常；不能让预期的断连变成未捕获异常。</p></div>
</div>

<div class="callout">503 表示当前服务不可用。只有健康检查或负载均衡策略配置为读取这个结果，它才会据此停止转发流量。</div>
<div class="note">同样要求响应 id 和配对日志；恢复数据库后应再次返回 200。此健康检查不等于“系统所有功能都正确”。</div>
<div class="debt mt-4">欠账 · 第 16 次课：部署、探针与健康策略</div>

<!--

本轮自动测试在临时 SQLite 中注入不可打开路径，检查 503，再恢复引擎检查 200。不是声称已停止过 PostgreSQL 验证。
