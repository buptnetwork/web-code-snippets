## 一、课程定位与能力目标

**定位**：面向"已用 AI 写过 Web 页面、但看不懂生成代码、无法约束 AI"的零 Web 基础学生。课程教**Web 全栈的一般性技术方案 + 支撑它的协议与理论**，以 FastAPI/Jinja2/PostgreSQL/SQLAlchemy/React/Vite 为实例载体，而非框架 API 培训。

**结业能力（可测量，对应你提出的四个缺口）**

| 缺口 | 能力标准（期末答辩逐条抽查） |
|---|---|
| Web 系统工作原理 | 能徒手画出请求全链路，并对任一环节说明"谁负责、失败表现、如何观察"；能用 request-id 在四处日志中追踪同一请求 |
| 后端框架工作机制 | 能解释装饰器如何变成路由表、依赖如何被求值、中间件穿越顺序、`def` 与 `async def` 的调度差异；能定位"接口变慢"到分层中的具体一层 |
| React 与状态管理 | 能说明重渲染触发条件与 key 的匹配后果；能对任一状态给出归属判定（URL / 服务端态 / 局部 / 全局）并说明理由 |
| 打包构建 | 能读懂 `dist/` 产物构成、说明 dev 与 build 两条不同链路、解释"类型错了为什么还能跑""前端 env 为什么必然泄漏" |
| **驾驭 AI** | 面对一段 AI 生成代码，能在 10 分钟内定位其所属分层、指出缺陷及后果、给出修复 diff；能写出含分层约束与验收标准的提示词 |

## 三、贯穿全课程的四条机制

**① AI 代码解剖台**（每次课开场 10 分钟，16 个案例）
给"能跑、看起来专业、含隐藏缺陷"的 AI 生成代码，学生答三问：**这行做什么 → 位于链路哪一层 → 缺陷与后果**。案例与当次课内容严格对应（见各次课"解剖案例"）。

**② 三张心智图**（学生自绘，每课更新，答辩必用）
请求链路图 / 数据流图（后端 DTO 链 + 前端三类状态流）/ 构建与部署产物图。这三张图是向 AI 下"改哪一层、不许动哪一层"指令的坐标系。

**③ 作业统一闭环：规格 → 生成 → 审查 → 修复**
提交物 = 提示词原文 + AI 输出 + 按本课评审清单标注的问题位置 + 修复 diff + 每条问题的一句话原理说明。**评分重心在审查与修复**。

**④ 累积文档《技术方案手册 + AI 协作规约》**
每次课末 5 分钟产出一页：通用方案图 + 跨栈对照 3 行小表 + 本课评审清单 + 提示词约束骨架。共 16 页，占总评 15%。

## 四、项目主线与里程碑

**主线项目**：带 AI 助手的问答社区（提问/回答/标签/投票/搜索 + AI 摘要与追问）。同一业务在课程中经历 **SSR 版 → 契约化 API → SPA 版 → 加固版 → 上线版** 五次形态演进，让学生亲历"技术方案选型的差异后果"。

| 里程碑 | 交付节点 | 验收要点（除功能外） |
|---|---|---|
| M0 骨架 | 第 1 次课 | 分层依赖方向正确；配置外置；统一异常与 request-id |
| M1 SSR 问答墙 | 第 4 次课 | 表单闭环 PRG；模板继承；中间件承载横切逻辑 |
| M2 数据层 | 第 6 次课 | 15 条 SQL/ORM 双实现对照；N+1 修复与索引前后定量 |
| M3 事务与迁移 | 第 7 次课 | 乐观锁 409；Alembic 可回滚；扩展—迁移—收缩说明 |
| M4 契约化 API | 第 8 次课 | problem+json；双分页；幂等键；OpenAPI 可交付；关键路径测试 |
| M5 React 组件化 | 第 10 次课 | 受控表单；key 正确；Profiler 优化前后定量 |
| M6 SPA 完整版 | 第 12 次课 | 竞态与取消；服务端态交给 query 层；状态归属表 |
| M7 认证与加固 | 第 14 次课 | 对象级授权；攻防四连 before/after 证据；CSP/SameSite |
| M8 AI 异步与流式 | 第 15 次课 | SSE 流式；队列重试与幂等消费；降级 |
| M9 上线 | 第 16 次课 | 部署可访问；压测报告 + 性能预算；故障定位报告 |

## 五、16 次课教学内容大纲

> 每次课 100 分钟（讲授+现场实操一体），课外投入 4–6 小时。统一时间配比：解剖台 10% / 栈实操 55% / 就地原理 25% / 判据与收尾 10%。

### 第 1 次课｜Web 系统全景与请求全链路

**定位**：建立坐标系。学生第一次看到"自己写的一行代码在整条链路的哪个位置"。

| 时段 | 内容 |
|---|---|
| 10′ | **解剖台**：AI 生成的接口——全部返回 `200 + {"success":false}`、读操作用 POST、密钥硬编码、异常直接抛栈 |
| 30′ | **实操**：应用工厂；六层目录 `routers/schemas/services/repositories/deps/config`；`pydantic-settings` 读 `.env`；Pydantic 模型 + 路径/查询/体三类参数；`response_model`；健康检查端点 |
| 15′ | **实操**：全局异常处理器 + `X-Request-ID` 中间件 |
| 20′ | **黑盒**：一次请求的四处对照追踪——DevTools 报文 / 应用日志 / 断点栈帧 / SQL 日志，用同一 request-id 串起来 |
| 20′ | **原理**：分层架构与依赖方向（为什么 service 不许 import router）；横切逻辑归属判据（中间件 / 依赖 / 装饰器 / 服务层）；12-Factor 配置外置；HTTP 方法性质矩阵（安全/幂等/可缓存）与状态码判据（401 vs 403、400 vs 422、409 vs 412）——用学生自己刚写的端点逐个对表纠错 |
| 5′ | 跨栈卡（Flask/FastAPI/Django/Nest/Spring 的管线与路由落点）+ 评审清单 |

**评审清单**：方法与状态码是否符合语义矩阵？横切逻辑是否被复制进每个路由？配置密钥是否硬编码？是否有统一异常兜底？
**作业**：按闭环补 3 个端点；提交请求链路图 v1 + 一次完整四处追踪记录。

### 第 2 次课｜浏览器运行时、协议与缓存结论层

**定位**：前端"必要集"+ 现代协议与缓存的**结论**（原因在第 16 次课实证）。

| 时段 | 内容 |
|---|---|
| 10′ | **解剖台**：AI 生成页面——div 汤无语义、内联样式、`innerHTML` 拼接用户内容、同步 `<script>` 置于 `<head>` |
| 30′ | **实操**：语义 HTML + 表单元素全套；CSS 盒模型/选择器优先级/Flex/响应式断点（Elements 面板现场调试） |
| 20′ | **实操**：DOM 操作、事件委托、`textContent` vs `innerHTML`；`fetch + async/await` 消费第 1 次课接口并渲染列表 |
| 20′ | **原理+黑盒**：关键渲染路径与 `<script>` 阻塞、`defer/async`；浏览器事件循环与长任务（Performance 面板）；Lighthouse 实测 LCP/INP/CLS |
| 15′ | **协议与缓存结论层**：h1 队头阻塞 → h2 多路复用/HPACK → h3 QUIC 要点；**"已失效的 h1 优化"判定表**（雪碧图、域名分片、文件合并）；强缓存 vs 协商缓存、文件名指纹（"改了代码用户仍看旧页面"）；**状态载体地图**（Cookie 自动携带 vs Storage 不发送） |
| 5′ | 手动拼 DOM 的三个固有问题（为第 10 次课立论）+ 手册页 |

**埋点**（后续回收）：Cookie 自动携带 → 第 14 次课 CSRF；指纹与长缓存 → 第 9、16 次课；协议结论 → 第 16 次课压测验证。
**作业**：改造预习页面为语义化 + 三态渲染；提交 Lighthouse 前后对比与一条优化的原理说明。

### 第 3 次课｜后端框架机制 I：路由、校验、依赖注入

**定位**：把框架"魔法"变成可观察的数据结构。

| 时段 | 内容 |
|---|---|
| 10′ | **解剖台**：每个路由里重复手写鉴权与 DB 连接；`/posts/{id}` 注册在 `/posts/latest` 之前 |
| 25′ | **实操**：`Depends` 全套——分页依赖、Session 依赖、当前用户占位、子依赖、`yield` 依赖与清理 |
| 15′ | **实操**：把业务逻辑从路由抽到 `services/`（**先看到路由臃肿的痛感再抽**） |
| 25′ | **黑盒**：打印 `app.routes` 看装饰器变成了什么（path 正则、endpoint、response_model）；单步进 Starlette/FastAPI 看 `scope → Request`；打印依赖树与求值顺序 |
| 20′ | **原理**：ASGI 三元组与"框架只是它上面一层"；路由匹配顺序 bug 复现；**校验与序列化是两阶段**、422 结构如何生成、缺 `response_model` 导致密码哈希泄漏；DI 的价值与代价（可测试性 ↔ 隐式性调试成本） |
| 5′ | 跨栈卡（Depends / Provider / IoC 容器）+ 评审清单 |

**作业**：用依赖消除项目中所有重复逻辑；提交依赖树截图 + 一处"AI 写成中间件但应为依赖"的判断说明。

### 第 6 次课｜ORM 与查询性能｜**交付 M2**

| 时段 | 内容 |
|---|---|

### 第 7 次课｜事务、并发控制与迁移｜**交付 M3**

|---|---|

### 第 9 次课｜前端工程化：模块系统与构建工具链
