# 《Web 全栈开发（AI 协作导向）》教学大纲（修订版）

## 一、课程定位与能力目标

**定位**：面向"用 AI 写过 Web 页面、但看不懂生成代码、无法约束 AI"的零 Web 基础学生。教**半衰期长的 Web 基本原理 + 当前主流框架（FastAPI / React）的正确用法**，目标是能**清晰、可控地驾驭 AI 开发一般复杂度的单体 Web 应用**。

**不做的事**：不做框架 API 培训；不深入数据库内核、协议内核、分布式与运维纵深（给结论与判据，指明后续课程）；不承诺提升写代码速度。

**结业能力（可测量）**

| 缺口 | 能力标准 |
|---|---|
| Web 系统工作原理 | 徒手画出请求全链路，对任一环节说明"谁负责／失败什么样／在哪观察"；能用报文、应用日志、断点栈帧与局部变量、SQL 执行证据关联同一次执行，并说明 request-id 与各观察工具的证明范围 |
| 后端框架机制 | 说明装饰器如何变成路由表、依赖如何求值、中间件穿越顺序、`def` 与 `async def` 的选择规则；能把"接口慢/报错"定位到分层中的一层 |
| 数据层 | 能为业务画 ER 图并写出正确 DDL（约束、外键、索引）；能读懂 ORM 生成的 SQL；能识别并修复 N+1 与丢失更新 |
| React 与状态 | 说明重渲染触发条件与 key 的后果；对任一状态给出归属判定（URL／服务端态／局部／全局）并辩护 |
| 前端构建 | 读懂 `dist/` 产物、区分 dev 与 build 两条链路、解释"类型错了为什么还能跑""前端 env 为什么必然泄漏" |
| 安全与认证 | 能实现会话认证与对象级授权；能复现并修复 XSS／CSRF／注入／IDOR 各一例 |
| **驾驭 AI** | 面对一段 AI 生成代码，10 分钟内定位分层、指出缺陷及后果、给出修复 diff；能写出含分层约束与验收标准的提示词；能用 CI 门禁自动拦住不合格产出 |

## 三、贯穿全课程的四条机制（保留，微调）

**① AI 代码解剖台**（通常安排在开场，时长随本课主线调整）
给"能跑、看起来专业、含隐藏缺陷"的 AI 生成代码，答三问：**这行做什么 → 位于链路哪一层 → 缺陷与后果**。案例与当次课严格对应。第一轮开课只需备好 8 个精品案例，其余用**学生提交的真实 AI 代码（匿名化）**替代，逐年积累。

**② 三张心智图**（学生自绘，每课更新，期末必用）
请求链路图 / 数据流图（后端 DTO 链 + 前端四类状态流）/ 构建与部署产物图。

**③ 作业统一闭环：规格 → 生成 → 审查 → 修复**
提交物 = 提示词原文 + AI 输出 + 按本课评审清单给出的判断与验证证据；发现问题时附修复 diff 与原理说明。**评分重心在有依据的审查与修复，不要求 AI 必须出错，也不要求凑够错误数量。**

**④ 累积文档《技术方案手册 + AI 协作规约》**
每课末产出一页：方案图 + 判据表 + 本课评审清单 + 提示词约束骨架。共 16 页。

**课内时间配比（参考）**：解剖与诊断 15% ／ 读改实操 40% ／ 就地原理 30% ／ 判据与收尾 15%；按当次课任务调整，不机械套用。
**课外**：3–4 小时（其中 B 档实验有脚本与自动验收，1 小时以内）

## 四、项目主线与里程碑

**主线**：问答社区（提问／回答／标签／投票／关键词搜索 + AI 摘要）。形态演进：**SSR 版 → 契约化 API → React SPA → 认证加固版 → 上线版**。

> **持久层策略**：第 1 次课从提供数据访问的单文件应用起步，第 4 次课在回归保障下提取 repository；第 5 次课复用同步持久层。第 6 次课核对模型、约束与 SQL，第 7 次课替换数据访问实现并建立迁移链，不因实现变化改坏既有 HTTP 契约。SQLite 可用于第一课隔离验收，第 6—7 次课参考实验统一使用 PostgreSQL 16+。

| 里程碑 | 节点 | 验收要点（含自动化脚本） |
|---|---|---|
| M0 骨架与可观测 | 第 1 次课 | 可运行；GET 搜索/详情与健康检查符合规格；request-id 响应头和配对日志；配置外置；注明 `/boom` 的历史观察缺口 |
| M1 SSR 问答墙 | 第 5 次课 | 保留三个核心 JSON 端点与健康检查；表单复用校验、失败回填、提交成功后 303；模板转义；异常日志；同步/异步选择有据 |
| M2 数据层与迁移 | 第 7 次课 | 五表与约束一致；同契约 N+1 对照；失败不留半截数据；空库迁移到 head；副本上验证一次保数据的 upgrade/downgrade |
| M3 契约化 API + CI 全绿 | 第 9 次课 | 统一错误契约；稳定排序分页；≥8 条关键路径测试；CI 四道门禁通过 |
| M4 React SPA 完整版 | 第 13 次课 | 受控表单；key 正确；服务端态交给 query 层；状态归属表可辩护 |
| M5 认证授权与安全加固 | 第 15 次课 | 会话认证闭环；对象级授权；三项攻击 before/after 证据 |
| M6 AI 功能 + 上线 | 第 16 次课 | 流式 AI 摘要含超时与降级；部署可访问；上线前检查表 |

## 五、16 次课教学内容

> 每次课 100 分钟，常规课按 **95 分钟教学 + 5 分钟缓冲**组织。每课突出一个学生现场必做任务；其余区分教师演示、思路导读与课后自学。**详实课件不要求课堂逐页讲完；A 档是基础能力与必交验收，B 档是选做拓展，不以是否在课堂完成划分。**

---

### 第 1 次课｜Web 系统全景与请求全链路（单文件起步）

**定位**：看见请求经过，建立观察坐标系；不提前讲分层和框架设计。
**现场必做**：暂停并发，给一次目标执行保留报文、应用日志、断点栈帧与局部变量、SQL 执行四处证据。

- **课堂主讲 / A 档**：八环节三问表；先观察并发日志噪音，再引入 request-id；区分当前线程栈与完整请求链路；普通读取优先 GET，状态码表达结果但不能独自证明业务正确
- **教师演示 / A 档**：使用实际 v1/v2 单文件反例；缺失详情返回 200 的后果；合法 id 透传、响应头和日志；`/boom` 的未知异常观察缺口
- **课后基础阅读 / A 档**：URL、curl、状态码与工具卡；按模板迁移搜索、详情并增加探针，不设计独立框架
- **B 档**：把响应头 request-id 显示在页面；响应头本身是 A 档，不是选做
- **作业**：请求链路图 v1 + 同一次执行的四处记录 + `GET /questions`（success/data）、`GET /questions/{qid}`、`GET /healthz` 验收｜**交付 M0**

> **交接与边界**：课堂 v2 旧 POST 只用于取证；M0 必须改为 GET，第二课不要求兼容旧路径。curl 重发是另一次执行；SQL echo 默认没有 id，暂停并发后以边界日志辅助关联。无可见状态码不能证明请求未到应用，request-id 也不等于完整分布式追踪。

---

### 第 2 次课｜HTTP 判据与请求—界面闭环

**定位**：正确处理请求与界面；承接合格 M0 的 GET 搜索和 success/data，不改后端公开契约。
**现场必做**：修复搜索页，正确呈现 loading/success/empty/error，并核对报文与界面。

- **课堂主讲 / A 档**：方法性质与状态码；fetch 获得响应、HTTP 判断、正文读取、JSON 解析、结构检查、渲染的失败边界；form/label/button、defer 与安全 textContent
- **教师演示与导读 / A 档**：先修 null 的加载时机，再在隔离中间版本对照不安全渲染；query、urlencoded、multipart、JSON 的位置与编码；缓存短演示与 Cookie/Storage 条件表
- **课后基础阅读 / A 档**：完整方法/状态表、编码和四态代码；重试结合具体状态与幂等性，不把所有 catch 叫网络失败
- **B 档**：受控 ETag/no-cache 与强缓存、真实 JS 版本标记和指纹实验；Lighthouse 指标解读、HTTP 版本与优化适用条件
- **作业**：修复后的搜索页 + 四态及错误类别证据 + M0 方法/状态判断；已正确可保留并说明。缓存报告仅 B 档选交

> **边界**：500 JSON 不使 fetch 自动 reject，解析错误可能进入 catch；Cookie 自动携带有作用域和策略条件；no-cache 允许存储但复用前验证，不承诺 F5 必然产生固定结果。完整安全回到第 14—15 次课，构建优化回到第 10 次课。

---

### 第 3 次课｜路由选择与输入／输出契约

**定位**：约束数据进出，把声明与实际行为对应起来。
**现场必做**：在同一个内存 POST 实验中，证明非法输入未进入端点、普通返回的额外输出被过滤，并解释保证范围。

- **课堂主讲 / A 档**：路径/查询/JSON 参数；Pydantic v2 的 In/Out 模型；先 strip 再长度约束；422 结构；业务 JSON 响应必须经过明确出口契约约束，返回 dict 本身不是错误
- **教师演示 / A 档**：`/questions/{qid}` 与 `/questions/latest` 的方法/路径选择，按路径和方法查路由对象；直接 JSONResponse 绕过过滤、缺必填输出导致500；显式声明错误响应并核对 OpenAPI
- **课后基础阅读 / A 档**：三个业务端点的参数化 SQL 与显式字段映射、创建先提交再回应；前后端契约迁移与基础边界表
- **B 档**：更多边界组合、回答端点模板迁移、路径转换器、ASGI 与跨框架比较；PATCH 正式实现留到第 8 次课
- **作业**：列表、详情、创建三个核心业务端点 + 必保留 `/healthz`；输入/输出证据、持久化与基础边界验证、新旧契约快照。不要求预测必须出错

> **明确迁移**：GET 路径不变；列表 success/data → items/total/page，公开参数 page_size 默认20、范围1—50，page≥1；列表输出 id/title/created_at/author，详情/创建另含 body，创建201＋Location。同步页面适配器与渲染、字面关键词匹配口径及数据升级；探针200/503不变。404/409暂保留三字段错误，第四课再迁移。

> **保证范围**：结构校验不等于业务正确、授权或绝对安全；直接 Response 可绕过出口模型。OpenAPI 不自动推断所有 raise 或异常处理器的错误，声明与运行分别核对。

---

### 第 4 次课｜可控重构：依赖、职责与错误边界

**定位**：在不破坏既有契约的前提下修改系统；起始代码保留第三课声明式校验，展示正确但资源管理分散的实现。
**现场必做**：把三个核心业务端点的连接生命周期接入共享依赖，中途运行回归，解释权威位置与保留的重复。按真实工程统计，不预设四处分页。

- **课堂主讲 / A 档**：Depends、资源生命周期、一个业务函数的抽取、依赖方向；page_size 公开名不变；区分纯重构 R 与批准的错误契约迁移 E
- **教师演示与导读 / A 档**：函数作用域提交时序；业务异常到 HTTP 的映射；业务、校验、Starlette HTTP 与未知异常处理器；保留 Allow 等响应头，探针数据库503保持原正文；finally 日志与外层500补头
- **课后基础阅读 / A 档**：完整处理器、OpenAPI 与客户端同步、配置模型和敏感信息检查、失败回滚与退出失败验证。service 不含 HTTP 状态码，Engine 已有连接池
- **B 档**：依赖工厂、完整依赖树、认证方案比较；洋葱机制在第5课深化，事务系统讨论第7课，认证第14课，不全部塞给下一课
- **作业**：R 阶段重构 diff 与回归 + E 阶段四字段错误迁移 + 资源失败证据 + 变更影响说明；区分文件数与位置数，不按零重复、路由行数或固定目录评分

> **事务与错误边界**：普通短请求统一 `Depends(get_conn, scope="function")`，子依赖复用同一声明，确保提交先于成功响应。默认 request scope 退出在发送后，不能用于兑现该成功含义。预期失败先穿过事务边界回滚；按用户限流在端点执行前拒绝。

> **时间与保障**：取消本课20分钟小测，采用95＋5；详实参考可课后学习，A档验收仍必交。前四课即可运行教师回归检查，第9课再系统学习测试设计与CI。

---

### 第 5 次课｜请求执行方式与 SSR 表单闭环｜**交付 M1**

**定位**：同一套业务规则服务 JSON 与 HTML 两种客户端；把阻塞与重复提交转为可观察证据。
**现场必做**：单 worker 下对照 `async def + time.sleep`、`async def + await`、`def + time.sleep`，测并发 1/10 的吞吐、延迟与失败数，解释差异，不预定性能倍数。

- **课堂主讲 / A 档**：框架调度与普通函数调用的区别；同步栈的端点选择；Jinja2 继承与 HTML 自动转义；表单复用 `QuestionCreate`，422/409 回填，事务提交成功后 `303 → GET`
- **教师演示与导读 / A 档**：中间件顺序；`finally` 补日志与兜底处理器补 500 响应头的不同职责；验证 PRG 前后请求方法，不撤掉已有标题唯一规则来制造重复数据
- **课后自学 / B 档**：flash 与签名 Cookie；纯 ASGI 中间件；固定工作量 CPU 实验、高并发与多 worker 对照；连接池容量估算
- **作业**：M1 三个 HTML 页面 + 保留三个核心 JSON 端点和 `/healthz`；表单与异常路径证据；基础六组并发记录（可使用课堂数据）+ 一个端点的调用链判据说明

> **边界**：PRG 不等于幂等、并发防重或 CSRF 防护；完整认证与安全在第 14—15 次课。课堂使用本地受控延迟，不接真实外链。详实模板、错误分支与调度参考留在底稿，非全部现场独立编写。

---

### 第 6 次课｜数据建模与 SQL 基础

**定位**：由业务规则推导约束，再用小数据核对查询结果；不展开数据库内核。
**现场必做**：在可手算的数据上复现 `!=` / `NOT IN` 遇 NULL 的漏行，先说明业务口径，再用 `IS NULL` / `NOT EXISTS` 修复。

- **课堂主讲 / A 档**：五表 ER 的基数与可选性；围绕问题表说明类型、`NOT NULL/UNIQUE/FK/CHECK`；稳定排序分页与 `LEFT JOIN + count(a.id)`；SQL 逻辑执行顺序
- **教师演示与导读 / A 档**：应用预查不能替代数据库唯一约束；已有脏数据必须先核查处理；一个候选索引的前后计划、实际行数与耗时，不把“走索引”等同于“更快”
- **课后基础阅读 / A 档**：完整五表 DDL 与八条业务 SQL 对照，课堂只展开其中三条；按提供的结果校验练习，不再额外叠加四条必交查询
- **B 档**：隔离性能库中的十万行索引实验；复合索引、深分页与文本检索的拓展，允许结果不变快并解释原因
- **作业**：五表 ER/DDL 与约束验证；八条 SQL 的结果核对（重点说明三条）；一条查询的索引取舍证据；一次 AI 建模建议的审查，可保留合理建议

> **边界**：坏结构、脏数据、性能数据与合格 M1 分离；不往学生交付库灌故障数据。参考语法为 PostgreSQL 16+；清洗历史保留证据，第 7 次课建立与最终结构一致的迁移基线。

---

### 第 7 次课｜可观察的 ORM、事务与迁移｜**交付 M2**

**定位**：替换持久层实现，保持外部契约；能解释 ORM 发了什么 SQL、何时提交、结构如何演进。
**现场必做**：固定数据、页大小、排序和输出字段，计数覆盖 DTO 构建与序列化；对照 lazy 与 `selectinload`，定位 N+1 并核对响应相同。

- **课堂主讲 / A 档**：对象—行映射、identity map、Unit of Work 与 `flush/commit`；声明式模型和关系的必要子集；Session 注入；关系加载与聚合计数的取舍
- **教师演示与导读 / A 档**：短请求事务边界；函数作用域依赖确保提交先于成功响应；异常穿过边界回滚再转 409/HTML；Alembic 空库基线、审读改名脚本、副本上 upgrade/downgrade 与内容核对
- **课后基础阅读 / A 档**：五条 SQL 的 SQLAlchemy 对照（课堂展开列表和回复数）；完整模型与约束对齐；既有库先核对再 stamp，不把已有表误当成已生成基线
- **B 档**：全项目 N+1 扫描、加载策略对照、slug 分阶段上线与数据迁移；只用执行次数计数器不能宣称测得传输行数或网络字节
- **作业**：M2 核心功能持久化 + 一个代表性列表的同契约 N+1 证据 + 失败回滚和提交失败验证 + 空库建链与一次保数据回退记录；说明一处 ORM/Core/`text()` 选择，不强制改用原生 SQL

### 第 8 次课｜API 契约设计与写操作正确性

**现场必做**：两个并发请求"先查再改"投票 → **丢失更新**复现 → `version` 乐观锁 → 返回 `409`。

- **解剖台**：错误响应五种格式混用；投票用 GET；重试导致重复发帖；分页无稳定排序
- **A 档实操**：资源化 URI 与集合/单项设计；`PUT` vs `PATCH` 的实现差异；复用第 4 次课统一错误契约（含改写默认 422）；offset 分页 + 稳定排序；筛选/排序参数**白名单**；把 `/openapi.json` 固化为**交付给前端的契约**
- **就地原理**：**幂等性严格定义**与"重试为什么会重复发帖"（回收第 2 次课矩阵）；**乐观并发控制的思想**（→ 第 12 次课 ETag/`If-Match` 是同一思想的另一层）；白名单为何同时解决注入与可维护性
- **B 档**：用 `openapi-typescript` 从契约生成前端类型（可选加分，→ 第 10 次课）
- **作业**：契约化 API + 《API 契约说明》1 页 + 投票并发控制实现与并发证据

### 第 9 次课｜测试、CI 门禁、AI 协作规约与故障定位｜**交付 M3**

**定位**：本课程的"总闸"。把约束 AI 从人肉审查升级为机器审查。
**现场必做**：让一段"能跑"的 AI 提交被 **CI 四道门禁**（lint / 类型 / 测试 / 契约）挡下，再逐条修绿。

- **解剖台**：AI 写的测试只断言 `200`、断言为空；覆盖率 90% 但拦不住 bug
- **A 档实操**：pytest + `TestClient`；测试隔离（每用例事务回滚）；fixture 分层；`dependency_overrides` 替换真实依赖；写 8 条关键路径测试；**GitHub Actions 工作流**（ruff + `tsc --noEmit` + pytest + 契约校验）
- **A 档：AI 协作规约落地**：仓库规则文件（`CLAUDE.md` / `.cursorrules` / `AGENTS.md`）如何写分层约束、禁改目录、错误契约、测试要求；**规格先行**（先写验收标准与测试，再让 AI 实现）；**小步 diff、每步可回滚**，禁止一次生成 20 个文件；**让 AI 做评审与写测试**，以及"生成者自评为何效果差"；何时不该用 AI（无稳定验收标准、涉密上下文、核心抽象）
- **就地原理**：测试金字塔与替身类型（结论）；**覆盖率的欺骗性**（高覆盖 + 空断言现场演示）；DI 为何让测试变简单（回收第 4 次课）；**故障定位四步法**——复现 → 最小化 → 二分 → 假设验证，现场定位 1 个植入 bug
- **B 档**：植入 3 个 bug 的仓库定位报告（含 1 个仅并发下出现）；Playwright 冒烟 1 条（模板给定）
- **作业**：M3 交付（API + ≥8 条测试 + CI 全绿）+ 仓库 AI 规约文件 + 一次"AI 产出被门禁挡下并修复"的记录

### 第 10 次课｜前端工程化：模块、构建与类型护栏

**定位**：学生第一次看懂"`npm run build` 到底发生了什么"。
**现场必做**：在 `dist/` 里 `grep` 出前端 `.env` 里的 API 密钥。

- **解剖台**：前端 `.env` 放密钥；`import _ from 'lodash'` 让包体翻倍；lockfile 未提交；**AI 幻觉依赖包**

- **B 档**：产物体积报告（visualizer）+ 一次动态 `import()` 拆包

### 第 11 次课｜React 组件与渲染机制

**现场必做**：`key={index}` + 受控输入导致的内容错位现场复现与修复。

### 第 12 次课｜数据获取、副作用与服务端状态

**现场必做**：人为随机延迟**复现请求竞态**（旧响应覆盖新）→ `AbortController` / query 层修复。

- **解剖台**：`useEffect` 无清理、依赖数组缺项、`catch` 后静默；把服务端数据塞进全局 state 并手写同步
- **A 档实操**：`api client`（base URL、超时、统一解析错误契约、401 拦截）；`useEffect + fetch` 三态；抽出 `usePosts` 自定义 hook；引入 **TanStack Query**（缓存键、失效、重试、乐观更新与回滚）；后端配 CORS 并逐字段解剖**预检请求**（撤掉 dev proxy 做对照）
- **就地原理**：**同源策略**——请求发出去了，是浏览器不让你读；**服务端状态 vs UI 状态**，为什么服务端数据不该进全局 store；`useEffect` 的正确心智（同步外部系统，不是生命周期钩子）；闭包陷阱；`StrictMode` 双调用暴露了什么
- **B 档**：SSE 流式渲染练习（模板给定，为第 16 次课 AI 功能预备）
- **作业**：全部页面接入 query 层 + 竞态复现与修复说明 + "哪些状态我判定为服务端态"清单

### 第 13 次课｜状态归属、路由与渲染模式｜**交付 M4**

**现场必做**：筛选条件存在 `useState` → 刷新丢失、链接无法分享 → 迁移到 URL 态。

- **解剖台**：全局 store 里塞服务端数据；prop drilling 五层；用"前端隐藏按钮"当权限（埋点到第 14/15 次课）
- **A 档实操**：React Router（嵌套路由、路由参数与查询串、`lazy` 与第 10 次课代码分割衔接）；**URL 态**（`URLSearchParams` 同步筛选与分页）；prop drilling → **Context** → **`useReducer`** 组织全局 UI 态与表单状态机
- **就地原理**：**状态归属决策树**——能推导就不存 → 能放 URL 就不放内存 → 服务端态交给 query 层 → 其余就近；单一数据源与派生状态；Context 全量重渲染的代价与"何时才真的需要 store"
- **作业**：M4 完整 SPA + **状态归属表**（每个状态：类型、归属、理由）+ SSR 版与 SPA 版同功能的请求数/首屏对照说明

### 第 14 次课｜认证与授权

**现场必做**：现场解出 JWT payload（Base64 不是加密）；**越权改帖（IDOR）复现** → 对象级授权依赖修复。

- **解剖台**：token 存 localStorage、Cookie 无 `HttpOnly`、登出只删前端状态、密码用 SHA256、只在前端隐藏按钮当权限
- **A 档实操**：注册（唯一约束、强度校验、**bcrypt/Argon2 用推荐参数**、不泄漏账号是否存在）；登录**成功后重签会话 ID**；Cookie 属性逐项配置（`HttpOnly/Secure/SameSite/Max-Age`）并在 Application 面板验证；登出与"记住我"；`get_current_user` / `require_login` 依赖；**`get_owned_post` 对象级授权** + `require_role` 角色控制 + 审计日志；前端 401 拦截跳转 + `credentials:'include'` 与 CORS 配合（回收第 12 次课）
- **就地原理**：**认证 ≠ 授权**；401 vs 403 vs 404 判据（回收第 2 次课埋点）；为什么密码不能用通用哈希（GPU 吞吐一句话）；**会话固定攻击**为何要登录后重签；**Session vs JWT 决策矩阵**（含吊销难题）
- **作业**：认证授权闭环 + "本项目为何选 Session（或 JWT）"的 ADR + 一处 IDOR 修复证据

### 第 15 次课｜Web 安全基线与 AI 特有风险｜**交付 M5**

**现场必做**：存储型 XSS 偷 Cookie 冒充登录 → 转义/清洗 + `HttpOnly` + CSP 后复测失败。
**合规声明**：所有攻防仅限课程提供的本地靶场；严禁对任何真实系统实施，须签署确认书。

- **解剖台**：模板 `|safe` / `dangerouslySetInnerHTML` 渲染用户输入；排序字段拼接进 SQL；生产开 DEBUG；密钥进仓库
- **A 档实操**：清理 `|safe` 与 `dangerouslySetInnerHTML`、富文本白名单清洗；**参数化查询**替换全部拼接；**CSRF 防护**（SameSite + 同步器 token / 自定义头）；**安全响应头基线**（最小可用 CSP、`X-Content-Type-Options` 等）；上传文件类型与名称校验；`pip-audit` / `npm audit`；生产配置检查表
- **就地原理**：XSS 三型与**浏览器不替你转义的四个位置**；参数化查询原理一句话（数据不进语句）；**CSRF ↔ SameSite 因果链**（回收第 2 次课"Cookie 自动携带"）；纵深防御与最小权限；**AI 特有风险**——跳过鉴权、拼接 SQL、写死密钥、幻觉依赖包、复制过时不安全示例、**提示注入与 LLM 输出不可信**
- **B 档**：攻防三连（XSS / CSRF / 注入）before-after 证据
- **作业**：M5 安全加固报告（3 项攻击 before/after + 修复代码 + 原理说明）+ 上线前安全检查表逐项打勾

### 第 16 次课｜AI 服务集成与上线交付｜**交付 M6** + 课程收束

**现场必做**：请求内同步等 LLM 30 秒 → 超时 / 降级 / 流式改造的前后对照。

- **解剖台**：无超时无重试；LLM 输出直接 `innerHTML`；前端直接持有 LLM 密钥；无成本上限
- **A 档实操（AI 集成，约 40′）**：`httpx.AsyncClient` 调 LLM（回收第 5 次课异步判据）；超时 / 重试 / 降级（降级到非流式或缓存结果）；**SSE 流式端点 + 前端流式渲染**（回收第 12 次课）；**结构化输出**（Pydantic 校验 + 失败重试）；LLM 输出必须转义（回收第 15 次课）；成本与限流结论（token 预算、超时预算、用户配额）
- **A 档实操（上线，约 35′）**：环境变量与配置外置（回收第 4 次课）；前端产物静态托管 + **SPA fallback**（回收第 10 次课）；反向代理的位置与职责（**画图为主，不调优**）；健康检查；日志与 request-id 贯通；**迁移与发布的先后顺序**；单容器 Dockerfile + `docker compose up` 一键起（模板给定）；**上线前检查清单**（安全 / 性能 / 日志 / 回滚）
- **就地原理**：长耗时任务的三种形态选型判据——同步 / 流式 / 后台任务；性能基线：p95 与三个常见瓶颈层（DB 查询 / 阻塞调用 / 前端包体）的定位路径（回收第 9 次课四步法）；可观测性三支柱一句话
- **作业**：M6 上线 + 期末文档（三张心智图终版 + ADR ≥3 条 + AI 债清单 + 上线检查表）
