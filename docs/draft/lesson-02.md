## 〇、这次课要建立什么

**讲给学生的目标句**：你能写一个页面把接口数据显示出来，并说明加载中、成功、空、失败四种情况分别怎么来。

第 1 课已经建立：浏览器发请求，Uvicorn 接收，FastAPI 选择端点，函数返回数据。本课把注意力移到浏览器里面：**收到响应对象之后，还需要检查状态、读取正文、解析数据，最后更新 DOM。**

学生应在 Week 0 接触 `querySelector`、事件监听、`textContent`、对象与数组以及 Promise／`await` 的语法形状。本课使用原生 HTML 与 JavaScript，不引入 React、TypeScript、构建工具或前端框架选型。

课堂路线：**回顾接口 → 最少的 HTTP 判据 → 教师做通正常读取 → 学生补四态 → 用受控故障解释失败阶段 → 安全显示用户文本**。不先给一个同时包含加载时机、请求和渲染错误的复杂页面让学生猜。

## 一、开场与交接：已经能用的后端是什么

**课堂 5 分钟。先确认正常起点，不现场开发数据库模块。**

本课使用第 1 课课后由教师发放的第 2 课起点包，不是让学生把第一课的硬编码 M0 自行升级成数据库工程。M0 的完成情况与本课教师包是否就绪分别核对。

### 1.1 本课固定接口契约

| 项目 | 约定 |
|---|---|
| 页面与 API | 同源，例如统一由 `http://127.0.0.1:8000` 提供；页面入口 `/`，静态脚本 `/static/app.js` |
| 搜索接口 | `GET /questions?keyword=...&page=1&page_size=20` |
| 参数 | `keyword` 默认空字符串；`page` 为整数，默认 1 且至少为 1；`page_size` 默认 20，整数范围 1–50；非法分页参数由教师基线返回框架 422 |
| 搜索规则 | 去掉关键词首尾空白，在标题或正文中做字面子串匹配；样本中的英文字母不区分大小写，`%`、`_` 不作搜索通配符 |
| 列表响应 | `{"items":[...],"total":匹配总数,"page":当前页}`；记录含 `id/title/body`，按 id 降序后分页 |
| 详情 | `/questions/{qid}` 保持第 1 课记录结构，缺失为 404；本课不开发详情页面 |
| 存活探针 | `/healthz` 仍返回 200 与 `{"status":"ok"}`，不检查数据库 |
| 错误正文 | 沿用框架错误体；本课不解析统一业务错误码，也不要求 request-id |

M0 的列表外壳只有 `items`，教师起点包已明确增加 `total/page`。本课从这个已扩展的版本开始，页面读取 `data.items`，不把完整响应对象当作数组；不再发生一次隐含的列表容器迁移。

### 1.2 先用同一组数据找回上节课

教师包沿用第 1 课三条虚构问题，依次为 id 3、2、1；其中只有 id 3 的标题包含 React。

| 输入 | 接口结果 | 页面应理解为什么 |
|---|---|---|
| 空关键词 | 200；三条记录，`total=3`、`page=1` | 正常结果 |
| `react` | 200；id 3，`total=1`、`page=1` | 正常结果 |
| `zzzz-no-match` | 200；`items=[]`、`total=0`、`page=1` | 正常完成但没有匹配项，不是 404 |

先在浏览器直接访问搜索接口，再打开教师已挂载的页面。教师说明：
> 上节课你看的是浏览器直接展示的 JSON。今天我们写页面脚本，让它自己请求这些数据，再决定用户该看到什么。

## 二、HTTP 的最少判据：方法、状态与正文

**课堂 12 分钟。只讲当前读取链路需要的概念，不铺完整状态码表。**

### 2.1 方法表达什么意图

本次搜索使用 GET：请求取得数据，不请求业务状态变化。服务端仍可能记录访问日志，这不改变读取意图。下一课会用 POST 创建问题，今天不实现写请求。

关键词放在 URL 查询串里。不要手工用字符串拼接用户输入；`&`、`#` 和空格可能改变 URL 的含义。教师用 `URLSearchParams` 生成查询串，学生核对 Network 中实际发出的参数即可。

```js
const query = new URLSearchParams({
  keyword: 'React & HTTP',
  page: '1',
  page_size: '20',
});
```

URL 编码是让字符正确传输，不是加密。课程只传虚构关键词，不放密码或其他敏感信息；不扩展到表单正文与 JSON 创建请求的编码比较。

### 2.2 状态与正文不是同一件事

| 观察 | 本课怎么解释 |
|---|---|
| 2xx | HTTP 层报告成功；还需检查正文能否解析、数据是否符合本页需要 |
| 4xx | 请求条件或目标等不满足；回收第 1 课的 404，并认识非法参数可能为 422 |
| 5xx | 服务端报告处理失败；本课用 500 做受控对照，不展开网关状态大全 |
| 没有可用响应对象 | 可能是网络、取消或浏览器策略等原因；不能自动归类为服务端 500 |

本课程搜索成功固定为 **200 + JSON**。空列表仍是成功响应；不要求所有接口都有可解析的 JSON，例如没有正文的响应不能无条件套用本页处理方式。

先写下本课最重要的一条规则：
> `fetch` 不会仅因为 HTTP 错误状态码而 reject。收到 500 也可能得到一个正常兑现的 Promise 和 Response；要由代码检查 `res.ok`，再决定是否继续。

## 三、教师构建：让正常结果先出现在页面上

**课堂 18 分钟。约 5 分钟接好表单与脚本，8 分钟走通请求与解析，5 分钟把结果放进 DOM。**

以下是配套练习包的文件约定，不表示本轮已经创建页面工程。教师提前提供 HTML 骨架与样式；正常示例先逐行走通，读取函数中的失败分支在第五单元回收解释。

### 3.1 HTML 骨架：提交事件从哪里来

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>问题搜索</title>
  <script src="/static/app.js" defer></script>
</head>
<body>
  <main>
    <h1>问题搜索</h1>
    <form id="search-form">
      <label for="keyword">关键词</label>
      <input id="keyword" name="keyword" type="search">
      <button type="submit">搜索</button>
    </form>
    <p id="status" role="status">输入关键词后搜索</p>
    <ul id="results" aria-busy="false"></ul>
  </main>
</body>
</html>
```

- `label` 与输入框的 id 对应；真实按钮和表单让鼠标点击与回车提交走同一个入口。
- 本例是带 `defer` 的外部经典脚本：文档解析完成后执行，脚本查找元素时这些 DOM 已存在。这里不比较所有脚本加载模式。
- 监听 `submit`，用 `preventDefault()` 阻止这一次表单提交的默认导航，才会进入我们的局部更新逻辑；仅有 `form` 不会自动变成异步请求。
- 初始提示不代表搜索得到空结果。页面初次打开不自动请求；用户第一次提交后才进入本课四态。

在 `app.js` 取得元素：

```js
const formEl = document.querySelector('#search-form');
const inputEl = document.querySelector('#keyword');
const buttonEl = formEl.querySelector('button');
const statusEl = document.querySelector('#status');
const listEl = document.querySelector('#results');
```

如果这里拿到 `null`，先查 HTML id、脚本地址与加载时机，不把页面初始化错误归为 API 失败。后续代码以这些元素已存在为前提。

### 3.2 读取函数：三个不同的东西

先区分变量代表什么：`response` 是响应对象，`response.json()` 读取并解析正文，`data` 才是可供访问字段的 JavaScript 值。`await fetch(...)` 并不等于“业务数据已经拿到并验证过”。

以下函数是教师提供并讲解的参考实现，放入同一份 `app.js`。课堂先沿正常分支走一遍，不要求学生重新设计错误类型体系。

```js
async function readQuestions(keyword) {
  const query = new URLSearchParams({
    keyword: keyword.trim(), page: '1', page_size: '20',
  });
  let response;
  try {
    response = await fetch(`/questions?${query}`);
  } catch {
    throw new Error('未获得可用响应，请检查连接或稍后重试');
  }
  if (!response.ok) {
    throw new Error(`服务返回 HTTP ${response.status}`);
  }
  let data;
  try {
    data = await response.json();
  } catch {
    throw new Error('响应正文读取或 JSON 解析失败');
  }
  if (!data || !Array.isArray(data.items)
      || !data.items.every(q => q && Number.isInteger(q.id)
        && typeof q.title === 'string' && typeof q.body === 'string')) {
    throw new Error('响应数据结构不符合本页约定');
  }
  return data.items;
}
```

正常路径只需要记住：**生成 URL → 等待 Response → 检查 `ok` → 等待 JSON → 检查用到的字段 → 返回列表**。

- `res.ok` 对应 200–299；本页按教师搜索接口的 200 JSON 契约工作。
- `.json()` 有自己的异步失败路径；它还涉及正文读取，不是只有“字符串转对象”这一步。
- JSON 语法合法，不代表一定有 `items`，也不代表记录包含可用的标题。这里仅检查本页要使用的字段，不宣称完成了整个 API 的 Schema 或业务正确性校验。
- 本课只渲染当前页，不使用 `total` 做分页。`total/page` 仍是后端契约的一部分，没有因页面暂时不用而删除。

### 3.3 渲染函数：把数据作为文本放进 DOM

正常示例从一开始就用安全文本写法；不是先让学生交付不安全页面，再到后面补救。

```js
function renderQuestions(items) {
  const fragment = document.createDocumentFragment();
  for (const q of items) {
    const li = document.createElement('li');
    const title = document.createElement('h2');
    const body = document.createElement('p');
    title.textContent = q.title;
    body.textContent = q.body;
    li.append(title, body);
    fragment.append(li);
  }
  listEl.replaceChildren(fragment);
}
```

`createElement` 建节点，`textContent` 放文本，`replaceChildren` 替换本次列表。片段用于先组织好节点，不要求学生背性能结论；使用普通节点逐项组织的等价实现也可以。

教师阶段先用这个最小事件入口完成一次正常搜索：

```js
formEl.addEventListener('submit', async event => {
  event.preventDefault();
  try {
    const items = await readQuestions(inputEl.value);
    renderQuestions(items);
  } catch (error) {
    statusEl.textContent = error.message;
  }
});
```

输入 `react`，观察 Network 的 GET 参数，再核对页面只显示 id 3 的标题和正文。这个阶段只证明正常读取已经接通，**还不是完整四态答案**。下一单元替换事件入口，不能把两个监听器同时保留而发出两次请求。

## 四、学生任务：补齐四态搜索页

**课堂 25 分钟。教师给 DOM 与读取／渲染函数；学生补状态切换和恢复，自主组织展示结构并构造一个空结果关键词。**

### 4.1 固定交互规格

| 状态 | 何时进入 | 本课文案与行为 |
|---|---|---|
| loading | 一次搜索开始，结果尚未确定 | “正在加载……”；清空上次列表，暂时禁用输入框与提交按钮 |
| success | 收到符合结构的非空列表，渲染完成 | “本页显示 N 条结果”；展示本页记录，不把 N 当作总匹配数 |
| empty | 收到符合结构的空数组 | “没有找到相关问题”；不显示上次列表，不当成请求失败 |
| error | 请求、HTTP 判断、正文／解析、结构或页面处理抛错 | 显示对应失败提示；不显示上次结果；已结束后允许再次搜索 |

成功和失败都要恢复输入框与按钮，保留用户输入的关键词。恢复网络或切回正常模式后，由用户再次提交；不做自动无限重试。

本课采用**一次只处理一个搜索**：除了禁用控件，还用一个 `busy` 标志守住重复提交入口。它只服务这个页面的串行交互，不是防抖、并发取消、服务器幂等或“最后一次请求获胜”的通用方案。第 12 课再处理多个请求交错返回。

### 4.2 学生实施与检查顺序

建议分配：8 分钟补 loading 与成功，5 分钟构造并处理 empty，7 分钟接错误与恢复，5 分钟连续回归。

学生自主选择列表项内部的 DOM 组织方式、状态提示位置及空结果查询输入；字段、请求参数与四态行为按给定契约，不自由改动接口。

先用空关键词和 `react` 跑通正常结果，再用自己构造的无匹配词验证 empty。教师随后开启有界延迟和已准备的失败模式，学生检查 loading 与 error。这里先会用故障开关，第五单元再解释失败阶段；学生不自己实现开关。

### 4.3 核对后的完整状态参考

以下代码与第三单元的元素引用、`readQuestions`、`renderQuestions` 组成最终 `app.js`，**替换此前的最小事件入口**。先让学生完成关键分支，再用它对照。

```js
let busy = false;

function setState(state, message) {
  statusEl.dataset.state = state;
  statusEl.textContent = message;
  listEl.setAttribute('aria-busy', String(state === 'loading'));
}

async function loadQuestions(keyword) {
  if (busy) return;
  busy = true;
  inputEl.disabled = true;
  buttonEl.disabled = true;
  listEl.replaceChildren();
  setState('loading', '正在加载……');
  try {
    const items = await readQuestions(keyword);
    renderQuestions(items);
    setState(items.length ? 'success' : 'empty',
      items.length ? `本页显示 ${items.length} 条结果` : '没有找到相关问题');
  } catch (error) {
    listEl.replaceChildren();
    setState('error', error instanceof Error ? error.message : '搜索失败，请稍后重试');
    console.error('搜索处理失败：', error);
  } finally {
    busy = false;
    inputEl.disabled = false;
    buttonEl.disabled = false;
    listEl.setAttribute('aria-busy', 'false');
  }
}

formEl.addEventListener('submit', event => {
  event.preventDefault();
  void loadQuestions(inputEl.value);
});
```

教师解释：

- 状态由这次搜索的进展驱动，不是先看到空列表就判定 empty。
- `finally` 在这里的成功或抛错路径结束后执行，所以恢复操作不应只写在成功分支。
- 外层 `catch` 也可能收到页面代码错误，不能看到它执行就断言断网；需要结合错误提示、Console 与 Network 定位。
- 参考实现没有客户端超时器。教师延迟必须有明确上限；请求若一直未完成，不能承诺 `finally` 已执行或控件会在固定秒数后恢复。超时与取消的实现不在本课新增。

## 五、受控对照：到底在哪一步失败

**课堂 15 分钟。先固定预测代码，再对照最终页面，避免把两种实现的行为混为一谈。**

### 5.1 两组预测题：先暂时拿掉 HTTP 判断

教师在隔离实验页中运行下面片段。固定条件：目标状态元素存在，响应正文完整可读，JSON 场景的正文语法合法；片段**不检查 `res.ok`、不检查数据结构、不调用列表渲染**。

```js
statusEl.textContent = '等待响应';
try {
  const data = await (await fetch('/questions?keyword=react')).json();
  statusEl.textContent = '已完成 JSON 解析';
  console.log(data);
} catch {
  statusEl.textContent = '进入 catch';
}
```

这段在教师预置的异步实验入口中执行，不直接复制到最终经典脚本顶层。让学生先预测：

1. 后端返回 **500 + 合法 JSON 错误体**，会进入 `catch` 吗？状态文字是什么？
2. 后端返回 **500 + HTML 错误页**，结果如何变化？失败发生在获得响应之前，还是读取／解析正文时？

教师答案：第一种完成 JSON 解析，片段不因 500 自动进入 `catch`，显示“已完成 JSON 解析”，但这不是业务成功。第二种已经取得 Response，随后 `.json()` 对该 HTML 正文解析失败，进入 `catch`。

由此强调：同样的 500，在缺少 HTTP 判断的代码里，可能因为正文格式不同而走不同分支。不能从这种现象推出“有时 fetch 会自动拒绝 500”。

### 5.2 回到最终实现：三种失败分别验证

| 固定故障 | `readQuestions` 中的失败位置 | 最终页面提示 |
|---|---|---|
| 500 + JSON 或 HTML | 已得到 Response；`!response.ok` 主动抛错，不继续按成功数据解析 | 服务返回 HTTP 500 |
| **200 + 非法 JSON 正文**，例如 HTML | HTTP 检查通过，`.json()` 失败 | 响应正文读取或 JSON 解析失败 |
| 页面已加载后，让本次请求无法获得可用响应 | `await fetch(...)` reject | 未获得可用响应，请检查连接或稍后重试 |

正式页面的“非 JSON”故障用 **200**，因为 500 HTML 会先被 HTTP 判断挡住，无法证明正式代码的 JSON 解析分支。预测实验中的 500 HTML 与正式页面中的 200 HTML 是有意固定的不同条件。

顺带核对 200 加 `{"items":null}`：JSON 解析成功，失败发生在结构检查，不能归因为断网或 JSON 语法错误。这项可复用教师自检记录，不新增第四份必交截图。

### 5.3 教师故障设施与证据条件

教师在本地隔离练习包提供正常、有界延迟、500 JSON、500 HTML、200 非 JSON、200 错结构等模式；模式切换保持页面地址和 API 调用关系不变，学生不用改业务 URL。具体操作入口随包说明，不假设 `/questions` 已经支持某个故障参数。

- 一次只启用一种故障，保留其余条件。每次切换后由用户手工提交，结束后恢复正常模式。
- loading 使用有限延迟，例如固定等待 1 秒再返回正常结果；这是教学延迟，不是性能测量结论。
- 网络失败在页面与脚本已加载后，用浏览器 Offline 或教师请求拦截制造；恢复后再搜索。不要刷新成一个无法加载的页面后，误把页面未启动当成 `fetch` 的错误处理。
- `fetch` 也可能因请求取消、非法配置或浏览器策略失败；取消通常表现为 `AbortError`。本次 Offline 只证明此条件下的行为，不能把全部 reject 都叫断网，也不能据此断言服务器从未执行请求。
- `.json()` 报错还可能涉及正文读取中断。正式提示合并称“正文读取或 JSON 解析失败”，不把每次失败都断言成后端输出了非法 JSON。

每条证据只记录：**启用的条件 → 目标请求或错误信息 → 页面状态 → 恢复后的结果**。模拟 fetch 可以检查分支，但没有真实 Network 请求，必须标明模拟，不冒充浏览器报文。

## 六、安全渲染：浏览器会把这段内容当成什么

**课堂 10 分钟。沿用已正确的 `textContent`，只在隔离容器中做一次对照；不写攻击脚本、不改共享数据库。**

教师准备两个空容器，用同一份无害文本比较：

```js
const sample = '<strong>这是用户输入，不是页面模板</strong>';
htmlBox.innerHTML = sample;
textBox.textContent = sample;
```

`htmlBox`、`textBox` 是教师隔离演示页已取得的两个元素，不属于最终搜索页接口。前者创建 `strong` 元素并显示加粗内容；后者显示包含尖括号的原始文字。先让学生说出差别，再查看 Elements 里的节点结构。

讲：
> `innerHTML` 告诉浏览器“按 HTML 解释它”；`textContent` 告诉浏览器“把它当文字”。当内容来自用户或接口时，我们不能因为它出现在 JSON 字符串里，就认为把它拼成 HTML 是安全的。

本实验只证明**解析方式不同**，没有弹窗也不表示完成了 XSS 攻防验证。正式页面始终把标题和正文写入文本节点；第 15 课再在专用靶场讲 XSS 与纵深防御。

当前边界：`textContent` 不是富文本清洗器，也不保证把用户值放进 URL、事件属性、样式或脚本上下文同样安全。本课不支持富文本；不要为了保留用户输入的标签改用 HTML 拼接。

## 七、回收：请求到页面之间多了哪几步

**课堂 10 分钟。给第 1 课已有链路图的浏览器一侧加注释，不要求重画一张复杂新图。**

```text
提交事件 → 构造查询 URL → fetch 得到 Response → 检查 HTTP → 读取并解析 JSON
                                                        ↓
页面显示 ← 安全文本渲染 ← 检查本页需要的数据结构 ← 解析结果
```

在相应箭头旁标注三种失败的位置，另标出 loading 从哪里开始、成功／空／错误在哪里确定。不要把服务器处理完毕、JSON 解析完毕和页面显示完毕画成同一个时刻。

### 常用写法卡 #2

| 常用路径 | 浏览器或代码做了什么 | 当前必须知道的边界 |
|---|---|---|
| `form + label + button` | 提供表单与键盘提交入口 | 监听 submit 并阻止默认导航，才进入本页局部更新 |
| 外部经典脚本 `defer` | 在文档解析后执行脚本 | 不是修复所有 DOM 错误，id 和脚本路径仍须对应 |
| `URLSearchParams` | 按查询串规则编码参数 | 编码不是加密，不手工拼接用户输入 |
| `await fetch(url)` | 发请求并取得可用的响应对象，或 reject | 不会仅因 HTTP 4xx／5xx 自动 reject |
| 检查 `res.ok` 后主动抛错 | 将 HTTP 失败导向错误分支 | 不能把服务器错误正文按成功列表继续处理 |
| `await res.json()` 与结构检查 | 读取、解析正文并核对本页需要的字段 | JSON 合法不等于字段和业务结果正确；正文只按本次路径读取一次 |
| `textContent` 与 DOM 节点 | 将用户内容作为文本展示 | 不是 HTML 清洗器，不扩展为所有输出上下文都安全 |
| 四态 + `finally` | 根据结果更新界面，在操作结束后恢复控件 | 没有结果还在等待，不是 empty；catch 不等于断网 |

### 出口三问与 AI 解释核对

1. `response` 与 `data` 各是什么？中间两次 `await` 分别在等什么？
2. 200 加空数组为什么是 empty，500 加 JSON 为什么应是 error？
3. 为什么恢复按钮放在 `finally`？它是不是意味着未完成的请求也已经结束？

AI 作为解释器：让它解释 `fetch → res.ok → res.json()` 的三步，选本课一种实际故障核对。解释正确就写接受理由与证据；不要求找到错误，不另做一次完整页面生成任务。
