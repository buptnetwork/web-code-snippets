## 〇、这次课要建立什么

**讲给学生的目标句**：你能启动一个服务、访问一个接口、改掉它的返回，并说出这次访问经过了哪些环节。

学生已在 Week 0 接触 Python 函数、列表与字典、循环、类型注解和装饰器的语法形状，也练过启动程序与打开 DevTools。本课不假定学生已经理解 Web 框架；会运行 AI 生成的项目，不等于能解释是谁调用了端点函数。

**核心解释目标**：地址栏中的路径，怎样选中你的函数、变成函数参数，再把返回值变成 HTTP 响应。

课堂只走一条递进路线：**看见成品 → 认识浏览器与服务器 → 写对一个列表接口 → 独立补详情 → 用一次断点解释 → 画出链路**。先建立正常实现，再比较“找不到”与“路径不存在”两个最小边界，不以分析故障工程开场。

## 一、开场：今天做出成品中的哪一小块

**课堂 5 分钟，含 2 分钟前置诊断。**

教师只展示成品的“列表 → 点开一条详情”两个动作，随即切到对应 JSON 响应。不展开登录、投票或 AI 摘要的实现。

讲：
> 页面很漂亮，但今天先不写页面。我们先让浏览器问“有哪些问题”和“这个问题是什么”，让自己的程序给出正确回答。下一课再把这些数据放进页面。

这里的“接口”先给工作定义：**客户端按约定的方法和地址提出请求，服务器返回约定的状态与数据**。函数是接口在服务器内部的一段实现，不等于整个接口。

## 二、必要铺垫：为什么有 Python 函数还需要框架

**课堂 15 分钟。先画浏览器、服务器、数据三方图，再展开服务器内部。**

### 2.1 普通函数调用与 Web 请求

普通 Python 程序中，我们写 `get_question(3)`，由当前程序直接传参调用。浏览器不能跨网络直接调用这个 Python 函数；它发出的是 HTTP 请求。服务器程序需要接收请求，应用需要判断该交给哪个函数处理。

| 角色 | 本例中负责什么 | 不负责什么 |
|---|---|---|
| 浏览器 | 向指定地址发送请求，展示收到的响应 | 不直接执行服务器里的 Python 函数 |
| Uvicorn | 监听端口、接收连接、处理 HTTP，并通过 ASGI 把请求交给应用 | 不替我们规定问题是否存在、该返回哪条业务数据 |
| FastAPI 应用 | 根据方法与路径找端点，处理声明的参数，调用函数，把普通返回值转换成响应 | 不自动理解问题数据，也不替我们写“找不到”的业务分支 |
| 端点函数 | 使用参数读取数据，返回结果或明确报告资源不存在 | 不自己监听端口、解析整段 HTTP 报文 |
| 数据来源 | 本课是固定列表，以后可换成数据库 | 换数据来源不意味着浏览器改为直接连数据库 |

ASGI 只解释为“服务器与 Python Web 应用之间的接口约定”，不展开协议事件。也不在这里铺开中间件、线程池、DNS/TCP/TLS 或反向代理的执行细节。

### 2.2 只拆今天会用到的 URL

用 `http://127.0.0.1:8000/questions/3` 指出：协议、主机、端口、路径。

- `127.0.0.1` 指运行浏览器这台机器的本机；同学打开自己的这个地址，不会访问到教师电脑。
- `8000` 是本次服务器监听的端口，不是业务编号。
- `/questions/3` 是路径，其中的 `3` 将作为问题编号。
- 在地址栏输入地址并访问，本次发起的是 GET。请求方法与路径共同参与路由匹配；不要求本课背完整方法表。

讲：
> Uvicorn 先把请求接进来，FastAPI 再按我们登记的规则找函数。你负责告诉它规则，以及找到函数之后该做什么。

## 三、教师构建：第一个正常列表接口

**课堂 20 分钟。先做出能运行的实现，再逐行解释；不要先罗列框架 API。**

### 3.1 环境与示例起点

教师提前提供已安装 FastAPI 与 Uvicorn 的独立练习环境、锁文件和运行目录。学生无需上课时首次安装依赖。

本稿约定练习目录中的入口为 `main.py`、应用对象为 `app`；这是后续配套工程的文件约定，不表示仓库中已生成该工程。所有数据均为虚构数据。

教师先写以下完整起始版：

```python
from fastapi import FastAPI

app = FastAPI()

QUESTIONS = [
    {"id": 3, "title": "React 的 props 是什么？", "body": "想知道组件怎样接收数据。"},
    {"id": 2, "title": "FastAPI 如何接收路径参数？", "body": "希望从地址取出问题编号。"},
    {"id": 1, "title": "浏览器怎样显示列表？", "body": "先确认接口能返回正确的数据。"},
]


@app.get("/questions")
def list_questions():
    return {"items": QUESTIONS}
```

在该练习目录、教师准备的 Python 环境中启动：

```bash
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

本课统一不用 `--reload`，减少调试时的进程干扰。修改代码后停止并重新启动，再访问验证；不是“保存文件就必然已经更新服务”。IDE 调试时由调试配置启动同一个模块，先停止终端中占用相同端口的进程。

### 3.2 逐行连接代码与结果

1. `FastAPI()` 创建应用对象，但这一行没有开始监听端口。
2. `@app.get("/questions")` 登记 GET 路径与函数的对应关系。应用加载时登记，匹配请求到来后才调用函数；不是装饰器不断主动运行函数。
3. `list_questions` 是 Python 函数名，不是 URL。URL 由装饰器中的路径声明决定。
4. 函数返回的是 Python 字典，`items` 是本课约定的列表字段；无需学生自己把它拼成 JSON 字符串。
5. 对这里的普通字典／列表返回值，FastAPI 生成 JSON 响应，默认成功状态为 200；这不等于自动保证返回了正确的业务数据。
6. 启动命令中的 `main:app` 表示从 `main` 模块取得 `app` 对象；Uvicorn 启动后继续等待请求，并非调用一次函数就退出。

### 3.3 浏览器里核对一次正常访问

访问 `http://127.0.0.1:8000/questions`。在 DevTools Network 中选中这一条目标请求，只看 Request URL、Method、Status 和 Response；需要在打开面板后重新访问才能捕获该请求。

应看到 200、JSON 内容类型，以及 `items` 中依次为 3、2、1 的三条问题。浏览器可能另发图标等请求，不以 Network 总条数作为本课考点。JSON 的折叠或美化方式取决于浏览器，不影响数据含义。

教师把 id 为 3 的问题标题改一个词，重启后再次访问。让学生指出响应里哪个字段变了，再恢复基准数据。这个小改动用于确认“我改的代码确实被当前服务加载”，不另交截图报告。

备用方式：浏览器面板不可用时，用 `curl -i http://127.0.0.1:8000/questions` 查看同一接口；这是另一次请求，不冒充前一次请求的记录。本课不依赖 `/docs` 的在线资源。

## 四、学生任务：独立补出详情接口

**课堂 25 分钟。前半段先完成正常详情，后半段处理不存在的编号。**

任务：实现 `GET /questions/{qid}`。找到时返回该记录；找不到时最终按 M0 契约返回 404。数据字段与 HTTP 契约给定，学生自主选择查找过程的组织方式，并选择一个与教师演示不同的编号验证。

### 4.1 先给任务，不立即给完整答案

教师提供的局部骨架如下，学生补全查找与返回：

```python
@app.get("/questions/{qid}")
def get_question(qid: int):
    # 在 QUESTIONS 中查找编号相同的问题，补全找到与未找到的分支。
    pass
```

提醒 `qid` 的名字与路径中的占位符一致；`int` 是本课要观察的声明，不展开 Pydantic 模型或全部参数约束。

建议时间分配：8 分钟写通正常查询，5 分钟换编号并检查返回对象，7 分钟比较缺失分支并收敛到 404，5 分钟回归列表和详情。提示按“指方向 → 局部线索 → 可对照片段”逐级给出。

### 4.2 用一个缺失输入认识 404

确认数据中没有 999 后，请学生先记录自己当前实现访问 `/questions/999` 的结果。如果当前返回 `None` 或 `{}`，就观察到 JSON `null` 或空对象仍可能配着 200；如果已经写对 404，解释其依据即可，不要求先人为写错。

讲：
> “函数运行结束”不等于“找到了这个问题”。我们需要明确告诉客户端：这个资源不存在。200 加空对象不能替代约定的 404。

完成讨论后再展示参考答案；先在文件顶部补充导入，然后替换骨架：

```python
from fastapi import HTTPException


@app.get("/questions/{qid}")
def get_question(qid: int):
    for question in QUESTIONS:
        if question["id"] == qid:
            return question
    raise HTTPException(status_code=404, detail="问题不存在")
```

不要把骨架和参考答案作为同一路径的两个实现同时保留。这里抛出的是框架认识的 HTTP 异常，FastAPI 将其转换为 404 和 `{"detail":"问题不存在"}`；不是让程序故意崩溃，也不需要本课自写统一异常处理器。

最小回归：访问 3 得到 id 为 3 的记录，访问 1 得到 id 为 1 的记录，访问 999 得到 404，再访问列表仍为 200。比较实际返回的 id 与正文，不仅看状态码。

## 五、机制观察：参数怎样进入函数

**课堂 15 分钟。只加一行日志、在详情函数入口打一处断点。两组问题先预测，答案后展示。**

在详情函数中、循环之前加入：

```python
print("收到详情请求，qid =", qid, "类型 =", type(qid).__name__)
```

这是观察当前参数的最小日志，不是生产日志方案。本课不要求日志文件、关联 id 或异常路径日志。固定虚构数据环境下手工访问一次即可，不制造并发噪音。

### 5.1 预测一：`"3"` 怎样变成 `3`

固定访问 `/questions/3`，每次只改变函数签名，然后重启应用：

| 签名 | 请先预测 | 教师答案与原因 |
|---|---|---|
| `def get_question(qid):` | 入口处的值与类型是什么？ | `"3"`，类型为 `str`；没有声明整数转换 |
| `def get_question(qid: int):` | 入口处的值与类型是什么？ | `3`，类型为 `int`；FastAPI 按路径参数声明完成转换后调用端点 |

先在入口观察，不把未标注版本能否查到记录混入类型判断：本数据的 id 是整数，未标注版本若直接比较 `3 == "3"` 会找不到，这是类型不同造成的。实验结束恢复 `qid: int`。

补充观察 `/questions/abc`：在最终的整数声明下得到框架 422，端点函数入口断点不命中。这里只建立“框架会按声明处理参数”的认识；422 正文结构与参数约束在第 3 课系统讲。

### 5.2 预测二：两种 404 分别是谁产生的

使用同一份最终代码，数据中无 999、应用未声明 `/not-a-route`。依次访问：

| 请求 | 是否进入详情函数 | 响应 | 原因 |
|---|---|---|---|
| `/questions/999` | 是，入口日志和断点可见 | 404，`detail` 为“问题不存在” | 路由匹配成功，业务查找没有结果，代码主动抛出 HTTP 异常 |
| `/not-a-route` | 否 | 默认 404，`detail` 为 `Not Found` | 框架找不到匹配路径，未调用详情函数 |

**同一个状态码不代表失败发生在同一处。** 这里的判断来自固定路径、函数入口与响应的对照，不是看到 404 就猜原因。

### 5.3 断点证据只要求到这个深度

学生保存一张本人操作的断点截图：能看清详情函数入口位置、`qid` 的值与类型，并用一句话说明“此时框架已经完成了什么”。不要求完整调用栈截图；当前线程的栈也不等于跨网络的完整请求链。

若停不住，先检查是否由 IDE 调试配置启动、是否访问了同一端口、是否恢复整数声明。教师可用已核验的录屏继续解释，但学生最终作业仍补本人操作证据；录屏不算学生实操。

## 六、学生画图：五个框串起这次请求

**课堂 10 分钟。图由学生完成，教师用正确数据流校对，不考绘图美观。**

```text
浏览器 ──HTTP 请求──▶ Uvicorn ──ASGI──▶ FastAPI ──参数──▶ 端点函数 ──读取──▶ 数据列表
浏览器 ◀─HTTP 响应─── Uvicorn ◀──────── FastAPI ◀─返回值── 端点函数 ◀─记录─── 数据列表
```

在图上只加四个标注：

1. Uvicorn 负责监听端口与接收请求。
2. FastAPI 按方法和路径匹配，并按声明处理参数。
3. 自己的函数负责从固定数据中选出正确记录。
4. 返回的 Python 对象由框架处理成 JSON 响应，再经服务器送回浏览器。

把 `/questions/3` 和变量 `qid = 3` 放到对应箭头上；再指出 `/questions/999` 的缺失发生在哪里。以后换成数据库主要改变数据来源，不是让浏览器越过服务器直连数据库。

## 七、收束：存活探针、常用写法卡与出口三问

**课堂 5 分钟。约 2 分钟演示探针，余下用于三问与作业说明；卡片随课提供，不逐条再讲一遍。**

在同一个应用中增加：

```python
@app.get("/healthz")
def healthz():
    return {"status": "ok"}
```

此时它只表示请求到达应用后能得到一个存活响应，**不连数据库，不验证所有业务功能，也不保证进程退出后还能返回错误响应**。第 4 课才增加数据库可用性检查；学生第一课不实现探针 503 分支。

### 常用写法卡 #1

| 常用路径 | 谁替你做了什么 | 常见错误与当前边界 |
|---|---|---|
| `app = FastAPI()` | 框架建立应用对象 | 创建对象不等于已经监听端口 |
| `@app.get("/questions")` | 框架登记方法、路径与处理函数 | 函数名不是 URL；装饰器不负责不断调用函数 |
| `{qid}` 与 `qid: int` | 框架提取路径值并按声明转换 | 转成整数不代表这条记录存在 |
| 返回 dict／list | 框架将本例的普通返回值转换为 JSON 响应 | 状态 200 不替你保证业务数据正确 |
| `python -m uvicorn main:app` | 服务器启动并接收请求 | 文件、对象名与端口必须对应当前工程 |
| `raise HTTPException(404, ...)` | 框架把已声明的 HTTP 异常转成错误响应 | 缺失资源不能用 200 加空对象代替 |
| Network 查看目标请求 | 浏览器展示实际请求和响应 | 面板不直接展示服务器内部执行；注意选中目标请求 |

**出口三问，也是作业概念表的三行**：

1. 谁接收浏览器请求，谁选择并调用你的函数？
2. 浏览器路径里的 `3` 为什么在函数入口成为整数？你在哪里观察到的？
3. `/questions/999` 与 `/not-a-route` 都返回 404，原因有什么不同？

学生用自己的代码与观察回答，不抄框架定义。教师答案分别回到“服务器与框架分工”“路径参数声明”“业务缺失与路由缺失”。

## 八、M0：能跑的三个接口

### 8.1 本课固定契约

以下是**第 1 课课堂版与 M0 交付版**的规格。使用上面的三条虚构记录；学生可在实验时改值，运行基准自检前恢复数据。Python 字典键顺序、JSON 空白与中文是否转义不作为判分依据。

| 接口与输入 | 状态及 JSON 结果 |
|---|---|
| `GET /questions` | 200；`{"items":[...]}`，三条记录按 id 3、2、1 排列，每条含 `id`、`title`、`body` |
| `GET /questions/3` | 200；直接返回 id 为 3 的完整记录，不额外套 `items` |
| `GET /questions/1` | 200；直接返回 id 为 1 的完整记录，防止实现写死某一条 |
| `GET /questions/999` | 404；`{"detail":"问题不存在"}` |
| `GET /not-a-route` | 框架默认 404；`{"detail":"Not Found"}` |
| `GET /questions/abc` | 框架 422；只核对状态与未进入端点，不逐字固定版本相关的校验正文 |
| `GET /healthz` | 200；`{"status":"ok"}`，无需数据库可用 |

本课只声明 `qid: int`，未声明正数范围，所以 0、负数也是可解析整数，在本数据中因不存在而返回 404；不要求它们返回 422。搜索参数、分页、`created_at`、作者、版本号、统一错误体、request-id 均不进入本次验收。对未实现的查询参数不作“已经支持搜索”的承诺。

### 8.2 一个作业包，不追加多套报告

学生提交：

1. 可运行的 `main.py`，包含列表、详情、探针三个接口；详情函数保留课堂最小日志。
2. M0 自检结果；自检器由教师提供，内部标注黑盒，学生不需要编写 pytest 用例。
3. 五框请求链路图 v1，以及一张能看清 `qid` 的本人断点截图。
4. 一页概念三问表，在表尾附一次 **AI 解释与运行结果核对**。

AI 只做解释器：让它解释自己代码中的路由声明或路径参数转换，用本次日志、断点或响应确认解释是否成立。解释正确时写接受理由即可；不要求找出 AI 错误，也不要求额外生成一套实现。常用写法卡补的个人例子可以直接引用三问表中的一行。

达标看三件事：**接口行为符合规格、详情不是写死单条结果、学生能解释这次请求**。不因缺少数据库、前端、架构分层或复杂观测设施扣分，也不拿截图数量代替理解。

选做：用手写 socket 接收一次本地 HTTP 请求，体会服务器替你省掉了什么。与必交分开，不影响 M0 达标。

### 8.3 教师自检器的制作要求

后续自检器只按上表检查行为，使用受控虚构数据，不要求特定循环写法或内部函数名。正常响应核对内容与 JSON 媒体类型；错误响应区分业务 404、路由 404、框架 422；同时确认列表与探针没有被详情改动破坏。“是否进入端点”由课堂日志与断点核对，不要求自检器通过匹配学生源码或日志文案来判断。

运行入口随新练习包一起提供，试讲前写入包内使用说明并实际跑通。**本稿目前没有承诺某条仓库验收命令已经适配新版 M0。** 自检结果不能替代真实浏览器访问与 IDE 断点验收。

## 九、第 1 课课后包与第 2 课交接

### 9.1 两个阶段明确分开

### 9.2 教师模块的调用约定

后续模块约定以 `question_store` 为文件内引用名，提供 `list()`、`get(qid)`、`search(keyword, page, page_size)`。这里规定的是交接接口，不声称模块已经存在。

| 调用 | 返回约定 |
|---|---|
| `question_store.list()` | 全部问题记录，按 id 降序 |
| `question_store.get(qid)` | 对应记录，找不到返回 `None`；端点沿用本课业务 404 |
| `question_store.search(keyword, page, page_size)` | `{"items":[...],"total":匹配总数,"page":当前页}` |

数据模块负责建库、装载固定种子、参数化查询、连接使用与关闭。学生只读调用关系；不能让第一次接触页面请求的学生同时调试数据库设施。教师不得用拼接用户输入的 SQL 换取示例短小。

### 9.3 第 2 课读取契约与固定样本

这是教师起点包在 M0 之上的**明确扩展**，不追溯增加 M0 要求：

- 列表保持 `GET /questions`；新增 `keyword`（默认空字符串）、`page`（默认 1）、`page_size`（默认 20，范围 1–50）。`page`、`page_size` 均为整数，`page` 至少为 1，非法分页参数返回框架 422；参数校验由教师端点基线提供，第 3 课再讲其声明机制。
- 关键词去掉首尾空白后，在标题与正文中做字面子串匹配；本课样本中的英文字母不区分大小写，`%`、`_` 不充当搜索通配符。固定数据按 id 降序，再分页；`total` 是分页前的匹配总数。
- 列表 JSON 从 M0 的 `{"items":[...]}` 扩展为 `{"items":[...],"total":...,"page":...}`。`items` 内仍是 `id/title/body`，第 2 课页面读取 `data.items`；不是把整个响应对象当数组。
- `/questions/{qid}` 与 `/healthz` 的已有响应保持不变。仍使用框架错误体；不提前引入第 4 课统一错误体或数据库探针。
- 该包的参数名与容器结构延续到第 3 课。第 3 课再按正式输入输出模型扩展字段、讲清校验，并同步更新页面；不得悄悄让前端仍依赖已经改掉的字段。

先沿用本课三条记录做教师自检，避免第二课一上来换数据、换接口又换页面：

| 请求 | 预期结果 |
|---|---|
| `/questions` | `items` 的 id 为 3、2、1，`total=3`，`page=1` |
| `/questions?keyword=react` | id 为 3 的一条，`total=1`，`page=1` |
| `/questions?keyword=zzzz-no-match` | 200，`items=[]`，`total=0`，`page=1`；无匹配是正常空结果，不是 404 |
| `/questions?page=2&page_size=2` | id 为 1 的一条，`total=3`，`page=2` |

教师包还需核对带首尾空白与不同大小写的关键词、超出结果范围的页以及非法分页参数；把输入和预期随包提供，学生不在第一课实现它们。

### 9.4 第二课开场必须已有的条件

1. 教师提供的页面骨架与 API 从**同一源**访问，例如统一为 `http://127.0.0.1:8000`；不能一边双击 `file://` 页面、一边请求另一个源，再让学生临场处理 CORS。

4. 后端 500、非 JSON 响应与网络失败的受控演示设施由教师预置，正常数据与故障模式可复位；只在第 2 课引入，不成为 M0 的额外端点要求。
