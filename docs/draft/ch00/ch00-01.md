# 讲一：心智模型、协议报文与工具链

## 0.1 你以前写的东西跑在哪里

时长: 10min

要求: 这一节纠正一个极常见的错误心智模型——很多学生认为"我写的代码就是在浏览器里跑的"。**必须靠演示纠正，不能靠说明。** 做法是让一个前后端分离的小页面先正常工作，然后当场杀掉后端进程，让页面变成一个空壳。学生要看到"页面还在、数据没了"这个具体现象。这一节不要引入任何术语层级，只要建立"两个进程"这一个概念。

内容:
- 客户端和服务端是**两个进程**，通常在两台机器上；它们之间**只有报文往来**，没有别的联系
- 浏览器里跑 HTML / CSS / JavaScript；服务端跑 Python / Node / Java
- 三种形态先建立轮廓（第 12 次课正式比较）：
  - 纯静态页面：只有客户端，没有服务端逻辑
  - 服务端渲染：服务端拼好完整 HTML 发过来（第 4 次课做）
  - 前后端分离：服务端只发数据，浏览器拿到数据后自己画（第 12 次课做）
- 你以前用 AI 生成的项目，大概率是第三种

图: 左边一个方框写"浏览器进程（你的电脑）"，右边一个方框写"服务端进程（可能在另一台机器）"，
    中间只有两条箭头：一条"请求报文"往右，一条"响应报文"往左。
    两个方框内部各标出跑的是什么语言。**中间不要画任何其他连线**——
    这张图要传达的正是"它们之间除了报文什么都没有"。

现场演示: 打开一个前后端分离的小页面 → 正常显示数据 → 在终端 Ctrl+C 杀掉后端 → 刷新页面
预期输出: 页面框架、按钮、样式都还在，但数据区域空了或显示报错；浏览器控制台出现网络请求失败

讲: 先问一个问题：你以前用 AI 写的那个网页，代码到底在哪儿跑？
很多人的印象是"就在浏览器里跑"。这个印象是错的，而且错得很关键。
你看这张图，左边浏览器，右边服务端，这是两个进程，很可能在两台不同的机器上。
它们之间只有一件事——发报文。没有共享内存，没有共享变量，什么都没有，只有报文。
我现在演示一下。这个页面现在好好的，有数据。我去终端把后端进程杀掉。
（杀掉，刷新）你看，页面还在，按钮还在，样式还在，但数据没了。
为什么？因为页面这些东西是浏览器手里的，后端死了不影响它。但数据是要去问后端的，后端死了就问不到。
这就是"两个进程"的直接证据。这门课接下来十六次，一大半时间在讲右边那个方框里面的事。

## 0.2 URL 解剖与 HTTP 报文四部分

时长: 15min

要求: 这一节是第 1 次课能看懂 `curl -i` 输出的前提，**必须让学生亲手发一次请求并逐行指认报文**，不能只看图。
      用我们自己提供的 `demo_server.py`（40 行纯标准库），不要用公开 API——理由有三：完全离线可复现、我们能控制响应头的内容、而且它会把学生发来的请求头**原样回显**，学生能看到"原来 curl 帮我发了这么多东西"。这个回显是本节最有效的一个瞬间。
      方法和状态码这里**只建立"有这回事"的认知**，判据留给第 1 次课 1.5.4，不要提前抢。

内容:

URL 六段解剖：
```
http://127.0.0.1:8000/hello/world?page=2&size=10#top
└协议┘ └──主机──┘└端口┘└──路径──┘└────查询串────┘└片段┘
```
- 会被发到服务端：路径、查询串
- **不会**被发到服务端：片段（`#top` 只有浏览器自己用）

请求报文四部分：
```
GET /hello?page=2 HTTP/1.1          ← 起始行：方法 + 路径 + 协议版本
host: 127.0.0.1:8000                ← 请求头（可以有很多行）
user-agent: curl/8.4.0
accept: */*
                                    ← 空行：头和体的分界
（请求体，GET 通常没有）
```

响应报文四部分：
```
HTTP/1.1 200 OK                     ← 状态行：协议版本 + 状态码 + 原因短语
Content-Type: application/json      ← 响应头
Content-Length: 214
X-Demo-Server: lesson00
                                    ← 空行
{"message":"hello", ...}            ← 响应体
```

先认脸不求深解的四个头：`content-type`（体是什么格式）、`content-length`（体多长）、`location`（新资源在哪，第 1 次课创建成功时会见到）、`cookie`（第 13 次课的正题）。

方法与状态码只记轮廓：GET 读、POST 提交；2xx 成功、4xx 你错了、5xx 我错了。

跟做 1: 起服务端并发第一个请求
```bash
uv run python snippets/lesson00/demo_server.py       # 终端 A，会一直占着
curl -i "http://127.0.0.1:8000/hello?page=2"         # 终端 B
```
预期输出:
```
HTTP/1.1 200 OK
Server: demo/0.1 Python/3.12.0
Date: ...
Content-Type: application/json; charset=utf-8
Content-Length: 231
X-Demo-Server: lesson00

{"message": "hello", "path": "/hello?page=2", "your_headers": {"Host": "127.0.0.1:8000",
 "User-Agent": "curl/8.4.0", "Accept": "*/*"}, "server_time": "2025-..."}
```
做完再继续。

跟做 2: 换成浏览器访问同一个地址，打开 DevTools 的 Network 面板，找到这个请求，
        看 Headers 标签里的 Request Headers 与 Response Headers。
        **对比 `your_headers` 的内容**：浏览器发的头比 curl 多很多。
做完再继续。

跟做 3: 让它返回一个 404 和一个 400
```bash
curl -i http://127.0.0.1:8000/nothing-here
curl -i -X POST http://127.0.0.1:8000/echo -H 'content-type: application/json' -d '{坏JSON'
```
做完再继续。

图: 请求报文与响应报文的四部分结构，上下并排。四部分各用一个色块区分，
    **空行那一行要显眼**——学生最容易忽略它，而它是头与体的唯一分界。

讲: URL 你们每天在用，但可能没拆过。看这一行，六段。
重点记两件事：路径和查询串会发给服务端；井号后面那个片段不会，那个只有浏览器自己用。
现在看报文。HTTP 报文长什么样？四部分，起始行、头、空行、体。就这四样，请求响应都一样。
注意这个空行——它是头和体的唯一分界，没有它服务端不知道头到哪儿结束。
现在跟我做。我给了你们一个四十行的小服务端，纯标准库，没有任何框架。你先把它跑起来。
（跟做 1）然后用 curl 请求它。看这个 -i 参数，意思是"把响应头也打出来"。
第一行 200 OK，然后是一堆头，然后一个空行，然后是体。四部分都在。
现在看响应体里这个 your_headers ——这是我故意设计的，它把你发过来的请求头原样退回给你。
你看，你只敲了一个 curl，它替你发了 host、user-agent、accept 三个头。
（跟做 2）现在用浏览器访问同一个地址，打开 F12 看 Network。
你会发现浏览器发的头比 curl 多得多——十几个。这些头都在干什么？第二次课整节课讲。
今天你只要建立一个认知：**每次请求都是一段有固定格式的文本，你能看到它的每一个字节。**
Web 开发里没有魔法，出问题的时候你总能把报文抓出来看。

## 0.3 JSON 的形状

时长: 7min

要求: 快讲。重点只有一件事——学生要能看着一段嵌套 JSON 说出"这是一个对象，里面有个数组，数组里是对象"。
      **例子直接用第 1 次课 422 响应体的真实结构**，这样第 1 次课演示校验失败时学生能立刻读懂那个 errors 数组。
      与 Python 的三处差异要点出来，因为学生手写 JSON 时百分之百会踩。

内容:
JSON 只有六种值：对象 `{}`、数组 `[]`、字符串 `""`、数字、布尔 `true/false`、`null`

与 Python 的三处差异（学生必踩）：
| JSON | Python |
|---|---|
| `true` / `false` | `True` / `False` |
| `null` | `None` |
| 键必须是**双引号**字符串 | 单引号也行，键还可以是别的类型 |

对应第1次课: 这一段是第 1 次课 1.4.3 校验失败演示的响应体，提前读一遍：
```json
{
  "type": "/errors/validation_error",
  "status": 422,
  "detail": "请求参数校验失败",
  "errors": [
    {"field": "title", "msg": "String should have at least 5 characters"},
    {"field": "body",  "msg": "String should have at least 10 characters"}
  ],
  "request_id": "9f2c1a4b7e30"
}
```
要能说出：最外层是**对象**，`errors` 是**数组**，数组的每个元素又是**对象**，各有 `field` 和 `msg` 两个键。

图: 上面那段 JSON 的嵌套结构树，三层：对象 → 数组 → 对象。

讲: JSON 就六种值，对象、数组、字符串、数字、布尔、null。没别的了。
三个坑，你们写的时候一定会踩：JSON 里是小写的 true false null，Python 里是大写的 True False None。
还有键必须用双引号，单引号 JSON 不认。
现在看这段——这是第一次课我演示校验失败时你们会看到的真实响应。你们现在就要能读它。
最外面是一个对象。里面 errors 这个键，它的值是一个数组。数组里每个元素又是一个对象，
每个对象有 field 和 msg 两个键。三层。
为什么要专门练这个？因为第十次课我们做前端表单，就是要把这个数组里的每一项，
按 field 的值找到对应的输入框，把 msg 显示在它下面。你读不懂这个结构，那节课就没法做。

内容:

**（1）路径与工作目录**
- `pwd` 看我在哪、`cd` 换地方、`ls` 看有什么
- 相对路径是相对**当前工作目录**，不是相对文件所在目录
- **为什么必须在项目根目录启动服务**：第 1 次课的配置类里写的是 `env_file=".env"`，这是相对路径。你在别的目录启动，它就找不到 `.env`，配置全用默认值，而且**不报错**——这是最难查的一类问题

**（2）进程与端口**
- 启动一个服务 = 起一个进程，它会一直占着终端；`Ctrl+C` 结束它
- 端口是进程独占的资源，一个端口同时只能被一个进程监听
- 端口占用的报错长什么样，以及两个解法：换端口 / 找到旧进程杀掉

**（3）环境变量与 `.env`**
- 环境变量是操作系统给进程的一组键值对，程序启动时能读到
- `.env` **不是 Python 语法**，它只是一个约定格式的文本文件，由库去读它
- 为什么用它：密钥、数据库地址这类东西不能写进代码（第 1 次课 1.5.3 讲原理）

**（4）包管理与虚拟环境**
- `uv sync` 按 `pyproject.toml` 装依赖；`uv run <命令>` 在项目环境里执行
- 虚拟环境为什么存在：不同项目要不同版本的同一个库
- 锁文件的作用：让你的机器和我的机器装出**完全一样**的版本

**（5）Git 最小闭环**
- `git clone` / `git status` / `git add` / `git commit -m` / `git push`
- `.gitignore` 为什么必须包含 `.env`：**提交过一次的密钥，删不掉**，只能去吊销重发（第 1 次课 1.5.3、第 16 次课再讲）

## 0.5 报错怎么读

时长: 10min

要求: 这是被严重低估的一项技能。零基础学生看到 traceback 的第一反应是**滚到最上面看**，
      而正确读法是**从最下面往上看**。这个反直觉必须明确说出来并示范。
      三段报错文本已在 `traceback_samples.md` 里给好，请全文上屏，因为学生要练"在一大段文本里找到关键的两行"。
      这一节直接支撑第 1 次课 1.4.3 的 500 演示，以及第 16 次课的定位四步法。

内容:

**读 traceback 的三步法**
1. 看**最后一行**：异常类型 + 消息。这告诉你"发生了什么"
2. 从下往上找**第一个属于你自己代码的文件**。这告诉你"从哪儿开始查"
3. 中间那些库文件的帧先跳过——它们通常只是传递者，不是原因

**三种最常见报错的形状**

| 报错 | 通常的真实原因 | 先检查什么 |
|---|---|---|
| `ModuleNotFoundError: No module named 'x'` | 依赖没装 / 工作目录不对 / 少了 `__init__.py` | 我在哪个目录？我用 `uv run` 了吗？ |
| `ImportError: cannot import name 'y' from partially initialized module` | **循环导入**（0.12 现场制造） | 两个文件是不是互相 import 了？ |
| `ValidationError: field required` | 配置或请求数据缺字段 | 看它说的是哪个字段（第 1 次课开场就会见到） |

对应第1次课: 第 1 次课我会故意在服务层插一行 `1 / 0`，
让学生看到"栈只进日志、不进响应体"。那时你要能读出这段栈：
```
ERROR [7c19...] app.error  unhandled error path=/api/posts/1
Traceback (most recent call last):
  ...（框架的十几帧，跳过）
  File "app/services/post_service.py", line 18, in get_post
    1 / 0
ZeroDivisionError: division by zero
```
→ 最后一行说"除零"，往上第一个自己的文件是 `post_service.py` 第 18 行 → **错误产生在服务层**。

跟做 7: 读 `traceback_samples.md` 里的三段报错，每段回答两个问题：
        ① 哪个文件哪一行？② 我该先去改什么？
做完再继续。

图（板书）: 一段 traceback，用两个箭头标注阅读顺序：
    箭头 1 指向最后一行（"先看这里"），箭头 2 从下往上指向第一个自己的文件（"再找这里"）。
    中间的库文件帧画成灰色（"先跳过"）。

讲: 读报错这件事，我要专门花十分钟，因为几乎所有人第一次都读错方向。
你看到一大段红字，本能反应是滚到最上面开始读。**错的。从最下面开始读。**
最后一行告诉你发生了什么——除零了、找不到模块了、字段缺了。这是结论。

它们绝大多数情况只是传递者，不是原因，先跳过。
三步：看最后一行，往上找自己的文件，然后去那一行。就这样。
第一次课我会故意写一个除零错误，你们要能一眼说出"这是服务层的问题"。

## 0.6 调试器：断点、单步、调用栈

时长: 25min

要求: **本讲高光，不可压缩。** 这一节直接决定第 1 次课高光页 1.4.4 的成败——
      第 1 次课只有 6 分钟展示"调用栈 = 分层图"，学生必须此刻就已经认识调用栈面板。

      分两段：
      前 12 分钟用 `stack_demo.py`（三层嵌套、无任何业务）把**"栈"这个概念**讲干净，
      压栈弹栈过程要**分步动态呈现**——这是高光页；
      后 13 分钟切到 mini 程序，让学生看到"栈帧的层次 = 我画的分层图的层次"，
      这是第 1 次课那个顿悟的预演版。

      **必须强调"为什么不用 print 调试"**，否则学生学完还是会退回去用 print。

内容:

**（1）为什么不用 print**
- `print` 只能看到你事先想到要看的那一个值
- 断点停下的那一刻，**当前所有变量、整条调用链**都摊在你面前，包括你没想到要看的
- 而且 print 要改代码、要删掉，断点不用

**（2）VS Code 调试器五个动作**
| 动作 | 干什么 |
|---|---|
| 在行号左边点一下 | 设断点 |
| F5 | 启动调试，跑到断点处停住 |
| F10 单步跳过 | 执行这一行，不进入函数内部 |
| F11 单步进入 | 执行这一行，**进入被调用的函数里面** |
| F5 继续 | 跑到下一个断点或结束 |

**（3）四个面板**
- **Variables**：此刻所有变量的值
- **Call Stack**：我现在在哪、我是被谁调进来的 ← **本节重点**
- Watch：盯住某个表达式
- Debug Console：在断点处直接执行代码试试

**（4）栈是什么**（高光段）
- 函数被调用时，一个"帧"被**压**到栈上；函数返回时，这个帧被**弹**掉
- 栈底是程序入口，**栈顶是你现在停的位置**
- 所以读调用栈就是在回答两个问题：**我在哪？我是怎么来的？**

用 `stack_demo.py` 演示：
```python
def level3(n):
    total = n * 2
    return total            # ← 断点打这里

def level2(n):
    return level3(n + 1)

def level1(n):
    return level2(n * 10)

if __name__ == "__main__":
    print(level1(3))
```
断点命中时的 Call Stack（栈顶在上，与 VS Code 一致）：
```
level3   ← 我现在在这里，n = 31
level2   ← 是它调用我的，n = 30
level1   ← 是它调用 level2 的，n = 3
<module> ← 程序入口
```

图: 高光页。三层嵌套调用的压栈弹栈过程，**分步呈现**：
    第 1 步 `<module>` 入栈 → 第 2 步 `level1` 压上去 → 第 3 步 `level2` 压上去
    → 第 4 步 `level3` 压上去（断点命中，此时栈高 4）
    → 第 5 步 `level3` 弹出，返回值 62 交给 level2 → 逐层弹出直到只剩 `<module>`。
    每一步要能看到栈的高度变化和当前帧的参数值。
    这是全课程唯一一次把"栈"讲干净的机会，请做扎实。

跟做 8: 在 `stack_demo.py` 的 `return total` 处打断点，F5 启动，
        在 Call Stack 面板里点击每一帧，观察 Variables 面板跟着变化。
        回答：`level2` 那一帧里 `n` 等于几？为什么不是 3？
做完再继续。

## 0.7 类型注解：给人和框架看，不给机器执行

时长: 10min

要求: 这一节要打掉一个具体的误解——很多学生以为写了 `x: int` Python 就会检查类型。
      **必须现场演示传错类型照样运行**，而且要让学生先预测再看结果。
      这个演示在第 9 次课"TypeScript 类型错了为什么还能打包"会被再次回收，是一处刻意埋点。
      本节的落点不是语法，而是最后那条：**框架会读取注解来决定行为**——这是第 1 次课几乎所有"魔法"的来源。

内容:

四种写法：
```python
page: int = 1                          # 变量注解
def double(n: int) -> int: ...          # 参数与返回值
keyword: str | None = None              # 可能是 str，也可能是 None
items: list[Todo]                       # 列表里装什么
```

现场演示（`annotations_demo.py`）:
```python
def double(n: int) -> int:
    return n * 2

print(double(3))                 # 6
print(double("ab"))              # ← 先猜：报错？还是输出什么？
print(double.__annotations__)
```
预期输出:
```
6
abab                             ← 注解写着 int，传 str 照样跑，还跑出了结果
{'n': <class 'int'>, 'return': <class 'int'>}
```

那注解有什么用？三个用途，第三个才是关键：
1. 编辑器补全和跳转
2. 静态检查工具（mypy 等）在**运行前**报错
3. **框架会在运行时读取注解，并据此决定行为** ← 第 1 次课的一切"魔法"都来自这里

对应第1次课:
| 第 1 次课的代码 | 框架读了注解之后做了什么 |
|---|---|
| `page: int = Query(1, ge=1)` | 从查询串取 `page`，转成 int，检查 ≥1，不合格就返回 422 |
| `payload: PostCreate` | 把请求体的 JSON 按 `PostCreate` 的字段校验并构造成对象 |
| `secret_key: str`（无默认值） | 环境变量里没有它就**启动失败** |
| `-> PostOut` / `response_model=PostOut` | 只把 `PostOut` 列出的字段序列化出去 |

讲: 类型注解，先做个实验。这个函数写着参数是 int，返回是 int。我传一个字符串进去，你猜会怎样？
（停）报错？没有。它输出了 abab。因为字符串乘二就是重复两遍。
**Python 的类型注解不参与运行时检查，一行都不检查。** 这一点你现在就要接受。
那它有什么用？三个。前两个是编辑器补全、静态检查工具。第三个才是重点：
**框架会在运行的时候把这些注解读出来，然后决定自己该干什么。**
你看第一次课的这几行。`page: int = Query(1, ge=1)` ——
FastAPI 读到这个注解，就知道要从查询串里取 page、转成整数、检查是不是大于等于一，
不合格直接返回 422，你一行 if 都不用写。
`payload: PostCreate` ——它读到这个，就知道把请求体的 JSON 按这个类的字段一个个校验。
所以第一次课那些看起来像魔法的东西，来源就是这里：**注解本身不做事，但有人在读它。**
最后提一句：第九课我们讲 TypeScript，那里也是一样的道理——类型只在编译前起作用，
编译完就没了。所以那节课我会问你们一个问题：类型错了为什么代码还能打包成功？
答案跟今天这个演示是同一个道理。

## 0.8 类：把数据和规则装在一起

时长: 18min

要求: **重点。** 这一节涵盖第 1 次课 `config.py` / `schemas/` / `repositories/` / `services/` / `errors.py`
      五个文件的共同基础。**例子按第 1 次课的文件顺序给，形成"预览"效果**——
      学生学完这一节，第 1 次课那五个文件的骨架他已经全部见过一遍。

      最后那个"构造器接收依赖"是本节的隐藏重点，它是第 1 次课 1.2.5 和第 8 次课测试替换的伏笔，
      要点出"为什么不在类里面自己创建对象"这个问题，但不必给完整答案。

内容:

**（1）类与实例、`__init__`、`self`**
```python
class TodoService:
    def __init__(self, repo):       # 创建实例时自动调用
        self.repo = repo            # self 就是"这个实例自己"

svc = TodoService(repo=JsonTodoRepo())   # 这一行会去执行 __init__
svc.list_todos()                          # 等价于 TodoService.list_todos(svc)
```

**（2）"类属性 + 类型注解"是一种声明式写法**
这是学生最陌生、也是第 1 次课最高频的一种写法：类体里只写字段名和类型，不写任何方法。
```python
class PostCreate(BaseModel):        # 第 1 次课 schemas/post.py
    title: str
    body: str
    author: str

class Settings(BaseSettings):       # 第 1 次课 config.py
    env: str = "dev"
    debug: bool = False
    secret_key: str                 # 没给默认值 → 必填
```
它在说什么：**"我这个类有这些字段，各是什么类型，哪些有默认值。"**
父类（`BaseModel` / `BaseSettings`）会把这些声明读出来，替你生成校验、生成文档、去环境变量取值。

**（3）继承与属性覆盖**
```python
class AppError(Exception):          # mini/errors.py，第 1 次课同构
    code = "internal_error"
    exit_code = 1

class NotFoundError(AppError):      # 只改两个类属性，其他全继承
    code = "not_found"
    exit_code = 4
```
要能回答：`NotFoundError` 有没有 `__init__`？有——继承来的。（门槛测试第 3 题就考这个）

**（4）`@dataclass` 省掉了什么**
```python
@dataclass
class Todo:                          # mini/models.py
    id: int
    title: str
    done: bool
    created_at: str
    created_by: str = "local"        # 内部字段，展示时不输出
```
它自动生成了 `__init__`、`__repr__`、`__eq__`。手写等价形式对比给一次即可。

**（5）构造器接收依赖**（隐藏重点）
```python
class TodoService:
    def __init__(self, repo):       # 仓储从外面传进来
        self.repo = repo
```
不这样写会怎样：
```python
class TodoService:
    def __init__(self):
        self.repo = JsonTodoRepo()   # 自己在里面创建 → 换不掉了
```
问题在哪：想测试这个类的业务规则，就必须真的读写文件。第 1 次课 1.2.5 和第 8 次课会给完整答案。

**（6）参数写法三件事**
- 关键字参数 `f(title="x")` 比位置参数可读
- 默认值
- keyword-only 参数：`def add(self, *, title, created_by)` 中那个 `*` 的意思是
  **它后面的参数必须用名字传**，不能靠位置。第 1 次课的仓储方法全用这个写法

图: 左边"类"（一张图纸），右边由它造出的两三个"实例"（各有自己的数据）。
    另标出：类属性在图纸上（所有实例共享），实例属性在每个实例自己身上。

对应第1次课:
| 本节语法点 | 第 1 次课出现在 |
|---|---|
| 类属性 + 注解声明 | `config.py` 的 `Settings`、`schemas/post.py` 的 `PostCreate` / `PostOut` |
| 继承与属性覆盖 | `errors.py` 的 `NotFoundError` / `ConflictError` / `RuleViolation` |
| `@dataclass` | `repositories/post_repo.py` 的 `PostRecord` |
| 构造器接收依赖 | `services/post_service.py` 的 `PostService(repo=...)`、`deps.py` |
| keyword-only `*` | `repo.add(*, title, body, author, client_ip)` |

讲: 这一节讲完，第一次课那五个文件的骨架你就全见过了。
先是最基本的：类是图纸，实例是照图纸造出来的东西。`__init__` 在创建实例时自动跑。
self 就是"这个实例自己"，你调 svc 点某个方法，Python 悄悄把 svc 当第一个参数传进去了。
然后是第二种写法，这个你们最陌生，也是第一次课最常见的——**类体里只有字段名和类型，没有方法**。
你看这个 PostCreate，就四行，全是"名字：类型"。它在说什么？
它在说"我这个类有这几个字段，各是什么类型"。这是一种**声明**，不是代码。
那谁来用这个声明？父类。BaseModel 会把这些声明读出来，替你生成校验逻辑。
BaseSettings 会把这些声明读出来，去环境变量里挨个找值。
所以这类写法你要换个眼光看：**它不是在写逻辑，它是在填一张表格给框架看。**
再看继承。这个 NotFoundError，就两行，改了两个类属性。其他全从父类继承。
我问你们一个问题：NotFoundError 有没有 `__init__` 方法？有，继承来的。这个门槛测试会考。
dataclass 就是省掉手写 `__init__` 的工具，不神秘。
最后这一条是重点，你们先记住这个问题的形状，答案第一次课给。
看这个 TodoService，它的仓储是**从外面传进来的**，不是自己在里面创建的。
如果自己在里面 new 一个会怎样？你就换不掉了。想测这个类的业务规则，
就必须真的去读写文件。第一次课我会给出正式答案，那个东西叫依赖注入。

## 0.9 异常：跨层传递信息的手段

时长: 15min

要求: **重点。** 教学关键是**换视角**——不要把异常讲成"错误处理"，
      要讲成"内层想告诉外层一件事，但中间隔了好几层，异常是唯一能一次穿透过去的方式"。
      这个视角比"异常是处理错误的"更接近第 1 次课的真实用法（服务层抛领域异常，最外层统一翻译）。

      必须做一次**两种写法的正面对比**：服务层 raise 让上层翻译，vs 服务层自己返回错误码。
      这个对比是第 1 次课 1.2.4 和 1.3.1 的浓缩预演。

内容:

**（1）完整四段形态**（第 1 次课的中间件正好用了完整四段）
```python
try:
    result = do_something()
except SomeError:
    ...             # 出错了做什么
else:
    ...             # 没出错才做什么
finally:
    ...             # 不管出没出错，都要做（清理、reset）
```

**（2）异常有继承关系，捕获父类能接住所有子类**
```python
try:
    svc.add_todo("x")
except AppError as exc:          # 能接住 NotFoundError / ConflictError / RuleViolation
    print(exc.code, exc.detail)
```

**（3）自定义异常：为什么业务代码抛 `NotFoundError`，而不是直接返回错误码**

看 mini 的实际情况。`service.py` 里：
```python
def get_todo(self, todo_id: int) -> Todo:
    row = self.repo.get(todo_id)
    if row is None:
        raise NotFoundError(f"待办 {todo_id} 不存在")
    return row
```
`cli.py` 里，**整个程序只有这一处**在做翻译：
```python
except AppError as exc:
    print(f"错误[{exc.code}]：{exc.detail}", file=sys.stderr)
    return exc.exit_code
```

**（4）正面对比：两种写法**

| | 服务层 raise，最外层统一翻译 | 服务层自己返回错误码 |
|---|---|---|
| 服务层代码 | `raise NotFoundError(...)` | `return None, 4` 或 `return {"ok": False}` |
| 每个调用点 | 什么都不用写，异常自己往上冒 | **每一层都要检查返回值并往上传** |
| 换一种输出形式（命令行 → HTTP） | 只改翻译那一处 | 服务层里的错误码全要改 |
| 忘了处理 | 异常冒到最外层，一定会被发现 | 静默继续执行，**故障消失** |

**（5）异常怎么穿层**：`repo` 返回 None → `service` 抛异常 → 中间几层什么都不用写 →
最外层 `cli.main` 接住。**中间层完全不需要知道有异常这件事**，这就是它的价值。

图（板书）: 四个方框竖排（cli / service / repo / errors），
    一支箭头从 service 出发，**穿过中间层不停留**，直接到达 cli 的 except。
    旁边对照画第二种写法：每一层都要有一个"检查返回值"的小方块，逐级往上传。

对应第1次课:
- `errors.py` 的 `AppError` 家族与 mini 的**完全同构**，只是 `exit_code` 换成了 `status_code`
- 服务层三种失败 → 三种领域异常 → 三种状态码（404 / 409 / 422）的翻译链
- 最外层用 `@app.exception_handler(AppError)` 注册翻译函数——一处翻译，全站统一
- 解剖台反例正是第二种写法：每个函数自己 `return {"success": False, "message": str(e)}`，
  五个接口能有五种错误格式

讲: 异常这个东西，我想换个说法讲。你们以前学的可能是"异常用来处理错误"。
我换一个说法：**异常是内层想告诉外层一件事，但中间隔了好几层，异常是唯一能一次穿透过去的方式。**
看 mini 的实际代码。repo 查不到，返回 None。service 发现是 None，抛一个 NotFoundError。
然后呢？然后中间什么都不用写，这个异常自己一路冒到最外面的 cli，
cli 那里有一个 except，接住它，翻译成一句人话和一个退出码。
整个程序**只有这一处**在做翻译。
现在看另一种写法，就是 AI 特别爱生成的那种：service 自己返回一个错误码或者一个 success 字段。
区别在哪？三点。
第一，每一层调用它的人都得记得检查返回值，然后再往上传。忘一层，故障就消失了，程序继续跑，
最后你在数据库里看到一堆脏数据，根本不知道哪儿出的事。
第二，你要换输出形式的时候。mini 是命令行，翻译成退出码。第一次课是 HTTP，翻译成状态码。
第一种写法我只改翻译那一处，服务层一行不动。第二种写法，服务层里的错误码全得改。
第三，一处翻译意味着格式统一。第一次课那个 AI 生成的反例，
五个接口五种错误格式，前端得写五套解析逻辑。
所以异常不只是"处理错误"，它是一种**架构手段**。第一次课的 errors.py 跟 mini 这个是同构的，
你现在看懂了 mini 这个，下周那个你直接就能读。

## 0.10 装饰器：读懂 `@app.post("/posts")`

时长: 18min

要求: **本讲高光，且是讲二最难的一节。**
      目标**不是**会写装饰器，是能说出"这个 @ 符号让某件事在后台发生了"。

      核心制作要求：**等价展开必须分步揭示**。
      第一步只显示 `decorator = app.post("/posts")` 并停住，让学生意识到"括号里的东西先被执行了、
      返回了一个新的东西"；第二步才显示 `list_posts = decorator(list_posts)`。
      **两步之间要停**——这是全课程唯一一次把"带参数的装饰器是两步"讲干净的机会，
      一次给全就没有效果了。

      最后的 MiniApp 是第 1 次课和第 3 次课的直接预习，必须让学生**亲手跑一遍并看到打印出来的路由表**。

内容:

**（1）前提：函数是对象**
```python
def hello():
    return "hi"

f = hello              # 不加括号，就是把函数本身赋给 f
print(f())             # hi
print(hello.__name__)  # hello —— 函数有属性，说明它是个对象
```

**（2）无参装饰器：`@` 就是一行赋值的简写**
```python
def log(func):
    def wrapper(*args, **kwargs):
        print(f"要调用 {func.__name__} 了")
        return func(*args, **kwargs)
    return wrapper

@log
def hello():
    return "hi"

# 上面那两行完全等价于：
# hello = log(hello)
```

**（3）带参数的装饰器：它是两步，不是一步**（高光段，分步揭示）

```python
@app.post("/posts")
def create_post():
    ...
```
第一步（先停在这里）：
```python
decorator = app.post("/posts")      # 括号里的东西先执行，返回一个"装饰器"
```
第二步：
```python
create_post = decorator(create_post)
```

所以带参数的装饰器要写成三层嵌套函数，这也是为什么它看起来那么难读。

**（4）关键认知：装饰器最常见的用途不是改造函数，是登记函数**

学生的直觉是"装饰器给函数加了功能"。但第 1 次课见到的装饰器几乎全是另一类用途——
**把函数登记到某张表里，函数本身一点没变。**

| 第 1 次课的装饰器 | 它把函数登记到了哪里 |
|---|---|
| `@router.get("/posts")` | 路由表：`("GET", "/api/posts") → list_posts` |
| `@router.post("")` | 路由表：`("POST", "/api/posts") → create_post` |
| `@app.exception_handler(AppError)` | 异常处理表：`AppError → 那个翻译函数` |
| `@lru_cache` | 这个才是真的改造函数（加了缓存） |

**（5）自己实现一个：15 行的 MiniApp**（`decorator_demo.py`）
```python
class MiniApp:
    def __init__(self):
        self.routes = {}                       # 就是一个字典

    def route(self, path, method="GET"):        # ← 第一步，返回下面那个 decorator
        def decorator(func):                    # ← 第二步，接收被装饰的函数
            self.routes[(method, path)] = func   # 登记！函数本身没动
            print(f"[注册] {method} {path} -> {func.__name__}")
            return func
        return decorator

    def handle(self, method, path):             # 模拟"来了一个请求"
        func = self.routes.get((method, path))
        if func is None:
            return 404, "not found"
            return 200, func()

app = MiniApp()

@app.route("/posts")
def list_posts():
    return "帖子列表"

@app.route("/posts", method="POST")
def create_post():
    return "已创建"
```

预期输出:
```
[注册] GET /posts -> list_posts          ← 注意：这两行在 import 阶段就打印了，
[注册] POST /posts -> create_post          我还没调用任何函数
{('GET', '/posts'): <function list_posts at 0x...>,
 ('POST', '/posts'): <function create_post at 0x...>}
(200, '帖子列表')
(404, 'not found')
```
做完再继续。要能回答：那两行 `[注册]` 是什么时候打印的？为什么在我调用函数之前？

图: 高光页。装饰器两步等价展开，分步呈现。
    另附 MiniApp 的路由表示意：一个字典，键是 (方法, 路径) 元组，值是函数对象。

对应第1次课:
- 解剖台的第一行就是 `@app.post("/getPosts")`，第 1 次课 1.1.2 三问法的第一个示范对象
- 1.2.6 的 `@router.get("")` / `@router.post("")`
- 1.3.1 的 `@app.exception_handler(AppError)` —— 登记的不是路由，是错误翻译函数
- 第 3 次课会让你 `print(app.routes)`，把 FastAPI 真实的路由表打出来，
  你会发现它和你今天写的 MiniApp 是同一个东西，只是字段更多

讲: 这一节最难，你们可能要看两遍。但它值得，因为 @ 这个符号是你看 AI 生成的 Web 代码时
第一眼就撞上的东西，而百分之九十的人对它的理解是"这是框架的魔法"。今天我们把魔法拆开。
第一个前提：函数是对象。你可以把它赋给变量、传给别的函数、从函数里返回。
基于这个，@ 是什么？@log 加一个函数定义，完全等价于：函数定义完之后，再写一行 hello = log(hello)。
就这样，一行赋值的简写，没有任何魔法。
现在看带参数的，这个是重点。`@app.post("/posts")` ——
（第一步，停）先看括号。括号里的东西**先被执行**了，app.post("/posts") 跑了一遍，返回了一个东西。
我们叫它 decorator。注意此时你的函数还没被碰过。
（第二步）然后，这个 decorator 才被用到你的函数上：create_post = decorator(create_post)。
**两步，不是一步。** 这就是为什么带参数的装饰器要写三层嵌套函数，为什么它那么难读。
好，现在讲最重要的一件事，这一句你们记住：
**你在 Web 框架里见到的装饰器，大部分不是在改造函数，是在登记函数。**
`@router.get("/posts")` 干了什么？它把你的函数塞进了一张表，键是方法加路径。
函数本身一个字节都没变。`@app.exception_handler(AppError)` 也一样，
它把你的函数塞进另一张表，说"以后遇到 AppError 就调这个"。
不信？我们自己写一个。看这个 MiniApp，十五行，一个字典当路由表。
route 方法就是标准的两步：外层接路径，内层接函数，内层做的唯一一件事就是往字典里塞一条。
（跟做 9）你们跑一下。看输出——注意那两行"注册"，
它们是在 **import 这个文件的时候**就打印出来的，我还一个函数都没调用。
这说明什么？说明装饰器在定义函数的那一刻就执行了，登记这件事早就做完了。
第三课我会让你们把 FastAPI 真实的路由表打印出来，你会看到它和你今天这个字典是同一个东西，
只是键值里的字段更多。这时候框架就不神秘了。

## 0.11 async / await：只要求看懂形状

时长: 8min

要求: **本节的核心是划边界，而不是教内容。**
      第 1 次课只有中间件一个 `async def`，且课上完全不讲并发。
      这一节的唯一目标是让学生看到 `async def` 时不恐慌，并明确知道"第 4 次课整节课讲这件事"。

      **绝对不要展开事件循环、协程调度、任务、gather。** 那些是第 4 次课的正题，
      提前讲只会造成半懂的错误印象，而半懂比不懂更难纠正。
      本节末尾必须有一句明确的"到此为止"声明。

内容:

三条，仅此三条：
1. `async def` 定义的函数，**调用它不会执行**，会返回一个协程对象
2. `await` 只能写在 `async def` 里面，含义是"这里可能要等一会儿，先让别人干活"
3. 第 1 次课你只会在一个地方见到它：
```python
response = await call_next(request)
```
   现在只需理解成：**把请求交给内层去处理，等它回来。**

明确不讲、留给第 4 次课的：
- 事件循环是什么
- 为什么 `async def` 里不能写阻塞代码
- 什么时候该用 `def`、什么时候该用 `async def`，以及选错的后果
- 为什么第 1 次课的路由函数是 `def` 而不是 `async def`（第 1 次课调用栈里会看到
  `run_in_threadpool` 这一帧，届时教师会说明"这就是第 4 次课的内容"，本讲不解释）

对应第1次课: `middleware.py` 的 `async def dispatch(...)` 与那一行 `await call_next(request)`。
第 1 次课 1.4.4 的调用栈里可能出现 `run_in_threadpool` / anyio 的帧，
教师会明确告知"这是第 4 次课的内容，今天不展开"。

讲: 这一节很短，因为我今天故意不讲它。
你在第一次课会见到一个 async def，就一个，在中间件里。你只需要知道三件事。
第一，async def 定义的函数，你调用它不会执行，它返回一个协程对象。
第二，await 只能写在 async def 里面，意思是"这儿可能要等一会儿，我先让出去，让别人干活"。
第三，第一次课你只会见到这一行：`response = await call_next(request)`。
你把它理解成"把请求交给内层处理，然后等它回来"，就够用了。
到此为止。事件循环是什么、为什么有的函数要写 async 有的不用、写错了会怎样——
这些是**第四课整节课**的内容，我今天一句都不讲。
为什么不讲？因为半懂比不懂更麻烦。你现在建立一个错误的印象，第四课我还得先把它拆掉。
所以你在第一次课看到 async 的时候，就想"哦，这个第四课讲"，然后继续往下听。这就是正确反应。

## 0.12 包与模块：import 是怎么找到文件的

时长: 12min

要求: **重点。** 这一节看似基础，但它是第 1 次课"依赖方向"能被讨论的物理前提，
      也是学生实操中卡住频率最高的地方（0.4 跟做 6 已经让他们撞了一次）。

      **循环导入实验必须让学生亲手做坏一次。** 只讲"不要循环导入"没有任何效果，
      要让他们把 mini 弄坏、看到那句报错、再改回来。这个痛感是第 1 次课 1.5.1 讲
      "依赖必须有方向"时唯一能依靠的具体经验。

内容:

**（1）模块与包**
- 模块 = 一个 `.py` 文件
- 包 = 一个含 `__init__.py` 的目录
- `from mini.service import TodoService` → 去找 `mini/service.py`，从里面取 `TodoService`

**（2）从哪个目录开始找**
Python 从"当前工作目录 + 已安装的包目录"里找 `mini` 这个名字。
所以 0.4 跟做 6 里你 `cd ..` 之后就找不到了——**这不是代码的问题，是你站错了地方**。

**（3）`python -m mini.cli` 与 `python mini/cli.py` 的差别**

| | `python -m mini.cli` | `python mini/cli.py` |
|---|---|---|
| Python 眼里 | 我在运行 `mini` 包里的 `cli` 模块 | 我在运行一个孤立的脚本文件 |
| 搜索路径起点 | 当前工作目录 | **`mini/` 目录本身** |
| `from mini.errors import ...` | 找得到 | **`ModuleNotFoundError: No module named 'mini'`** |

结论：**运行包里的模块，用 `-m`。** 这条规则记住能省你好几个小时。

**（4）循环导入现场实验**

在 `mini/service.py` 的最上面加一行：
```python
from mini.cli import main          # ← 故意加的，加完立刻删
```
然后运行 `uv run python -m mini.cli list`。

预期输出:
```
ImportError: cannot import name 'main' from partially initialized module 'mini.cli'
(most likely due to a circular import)
```

发生了什么：`cli` 开始加载 → 它要 import `service` → `service` 又要 import `cli`
→ 但 `cli` 才加载到一半，`main` 还没定义出来 → 报错。

**这不是 Python 的缺陷，这是它在替你指出一个架构问题**：
`cli` 依赖 `service` 是对的（外层用内层），`service` 反过来依赖 `cli` 就说不通了——
业务规则凭什么要知道命令行怎么打印？

**（5）依赖方向：mini 里的箭头**
```
cli  →  service  →  repo
 ↘         ↓         ↙
      models / errors
```
箭头**只能单向**。`service` 里没有一处 import `cli`，所以第 1 次课把 `cli` 换成 HTTP 路由时，
`service` / `repo` 一行都不用改。

**（6）`grep -rn` 为什么能查出架构违规**
```bash
grep -rn "from mini.cli" mini/service.py mini/repo.py    # 应当无输出
```
对应第 1 次课的两条自查命令：
```bash
grep -rn "from app.repositories" app/routers/    # 应当无输出
grep -rn "fastapi\|starlette" app/services/      # 应当无输出
```
**架构约束不是一句口号，它是一条能跑出结果的命令。**

### `mini/repo.py`
```python
"""数据访问层。对应第 1 次课的 app/repositories/post_repo.py。

它只管存取，不懂任何业务规则。第 1 次课的仓储会在第 6 次课被换成 SQLAlchemy 实现，
而上面两层一行不改；本文件同理——把 JSON 文件换成数据库，service.py 不用动。
"""
import json
import logging
from datetime import datetime, timezone
from pathlib import Path

from mini.models import Todo

log = logging.getLogger("mini.repo")
DATA_FILE = Path("todos.json")


class JsonTodoRepo:
    def __init__(self, path: Path = DATA_FILE) -> None:
        self.path = path

    # --- 内部工具 ---
    def _load(self) -> list[Todo]:
        if not self.path.exists():
            log.info("READ %s -> 0 rows (文件不存在)", self.path)
            return []
        raw = json.loads(self.path.read_text(encoding="utf-8"))
        rows = [Todo(**item) for item in raw]
        log.info("READ %s -> %d rows", self.path, len(rows))
        return rows

    def _save(self, rows: list[Todo]) -> None:
        data = [row.__dict__ for row in rows]
        self.path.write_text(
            json.dumps(data, ensure_ascii=False, indent=2), encoding="utf-8"
        )

    # --- 对外接口（第 1 次课的仓储也是这几个方法） ---
    def list(self) -> list[Todo]:
        return self._load()

    def get(self, todo_id: int) -> Todo | None:
        for row in self._load():
            if row.id == todo_id:
                return row
        return None

    def title_exists(self, title: str) -> bool:
        return any(row.title == title for row in self._load())

    def add(self, *, title: str, created_by: str) -> Todo:
        rows = self._load()
        next_id = max((r.id for r in rows), default=0) + 1
        row = Todo(
            id=next_id,
            title=title,
            done=False,
            created_at=datetime.now(timezone.utc).isoformat(timespec="seconds"),
            created_by=created_by,
        )
        rows.append(row)
        self._save(rows)
        log.info("INSERT -> id=%s", row.id)
        return row

    def set_done(self, todo_id: int, done: bool) -> Todo | None:
        rows = self._load()
        for row in rows:
            if row.id == todo_id:
                row.done = done
                self._save(rows)
                log.info("UPDATE id=%s done=%s", todo_id, done)
                return row
        return None

    def delete(self, todo_id: int) -> bool:
        rows = self._load()
        kept = [r for r in rows if r.id != todo_id]
        if len(kept) == len(rows):
            return False
        self._save(kept)
        log.info("DELETE id=%s", todo_id)
        return True
```

### `mini/service.py`
```python
"""业务规则层。对应第 1 次课的 app/services/post_service.py。

注意这个文件"没有什么"：
  - 没有 import argparse、没有 import sys
  - 没有一个 print
  - 没有一个退出码数字
它不知道自己是在为命令行服务。所以第 1 次课把 cli.py 换成 HTTP 路由时，
本文件一行都不用改。
"""
from mini.errors import ConflictError, NotFoundError, RuleViolation
from mini.models import Todo
from mini.repo import JsonTodoRepo

MIN_TITLE_LEN = 2
BANNED_WORDS = ("摸鱼", "算了")


class TodoService:
    def __init__(self, repo: JsonTodoRepo) -> None:
        # 仓储从外面传进来，不在这里创建 —— 这样才换得掉、测得了
        self.repo = repo

    def list_todos(self) -> list[Todo]:
        return self.repo.list()

    def get_todo(self, todo_id: int) -> Todo:
        row = self.repo.get(todo_id)
        if row is None:
            raise NotFoundError(f"待办 {todo_id} 不存在")
        return row

    def add_todo(self, title: str) -> Todo:
        title = title.strip()
        # 只看这一次输入就能判断的 —— 格式规则
        if len(title) < MIN_TITLE_LEN:
            raise RuleViolation(f"标题至少 {MIN_TITLE_LEN} 个字，你给的是 {title!r}")
        hit = next((w for w in BANNED_WORDS if w in title), None)
        if hit:
            raise RuleViolation(f"标题包含违规词：{hit}")
        # 需要查系统里已有什么才能判断的 —— 业务规则
        if self.repo.title_exists(title):
            raise ConflictError(f"已存在同名待办：{title}")
        return self.repo.add(title=title, created_by="local")

    def finish_todo(self, todo_id: int) -> Todo:
        self.get_todo(todo_id)               # 不存在则抛 NotFoundError
        row = self.repo.set_done(todo_id, True)
        assert row is not None
        return row

    def remove_todo(self, todo_id: int) -> None:
        self.get_todo(todo_id)               # 不存在则抛 NotFoundError
        self.repo.delete(todo_id)
```

    sub = parser.add_subparsers(dest="command", required=True)

def main(argv: list[str] | None = None) -> int:
    logging.basicConfig(
        level=logging.INFO, format="%(levelname)-5s %(name)-12s %(message)s"

    args = build_parser().parse_args(argv)
    svc = TodoService(repo=JsonTodoRepo())      # 组装依赖：对应第 1 次课的 deps.py

    try:
        if args.command == "add":
            print("已添加：" + render(svc.add_todo(args.title)))
        elif args.command == "list":
            rows = svc.list_todos()
            if not rows:
                print("（空）")
            for row in rows:
                print(render(row))
        elif args.command == "done":
            print("已完成：" + render(svc.finish_todo(args.todo_id)))
        elif args.command == "delete":
            svc.remove_todo(args.todo_id)
            print(f"已删除 #{args.todo_id}")
    except AppError as exc:
        # ← 全程序唯一的错误翻译点
        print(f"错误[{exc.code}]：{exc.detail}", file=sys.stderr)
        return exc.exit_code
    return 0


if __name__ == "__main__":
    sys.exit(main())

## B. `demo_server.py`（0.2 用）

```python
"""一个 40 行的最小服务端，只为课前课演示 HTTP 报文，不是本课程的技术栈。

它会把你发来的请求头原样回显，方便你看清 curl 和浏览器各自替你发了什么。

运行： uv run python snippets/lesson00/demo_server.py
"""
import json
from datetime import datetime, timezone
from http.server import BaseHTTPRequestHandler, HTTPServer


class DemoHandler(BaseHTTPRequestHandler):
    server_version = "demo/0.1"

    def _json(self, status: int, payload: dict) -> None:
        body = json.dumps(payload, ensure_ascii=False, indent=2).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.send_header("X-Demo-Server", "lesson00")
        self.end_headers()
        self.wfile.write(body)

    def do_GET(self):
        if self.path.startswith("/hello"):
            self._json(200, {
                "message": "hello",
                "method": self.command,
                "path": self.path,
                "your_headers": dict(self.headers),   # ← 把你发的请求头退回给你
                "server_time": datetime.now(timezone.utc).isoformat(timespec="seconds"),
            })
        else:
            self._json(404, {"error": "not_found", "path": self.path})

    def do_POST(self):
        length = int(self.headers.get("Content-Length") or 0)
        raw = self.rfile.read(length).decode("utf-8")
        try:
            data = json.loads(raw) if raw else {}
        except json.JSONDecodeError:
            self._json(400, {"error": "bad_json", "你发的原始文本": raw})
            return
        self._json(201, {"received": data, "body_size": length})


if __name__ == "__main__":
    print("listening on http://127.0.0.1:8000   (Ctrl+C 退出)")
    print("试试： curl -i 'http://127.0.0.1:8000/hello?page=2'")
    HTTPServer(("127.0.0.1", 8000), DemoHandler).serve_forever()
```

## E. `decorator_demo.py`（0.10 用）

```python
"""装饰器的两个用途，以及一个 15 行的迷你路由表。

第 3 次课我们会把 FastAPI 真实的 app.routes 打印出来，
你会发现它和下面这个 self.routes 字典是同一个东西，只是字段更多。
"""

# ---------- 用途一：改造函数（少见） ----------


def log_call(func):
    def wrapper(*args, **kwargs):
        print(f"[调用] {func.__name__}")
        return func(*args, **kwargs)
    return wrapper


@log_call                 # 等价于： greet = log_call(greet)
def greet():
    return "hi"


# ---------- 用途二：登记函数（Web 框架里绝大多数装饰器都是这个） ----------


class MiniApp:
    def __init__(self):
        self.routes = {}                             # 路由表就是一个字典

    def route(self, path, method="GET"):             # 第一步：接住参数
        def decorator(func):                          # 第二步：接住被装饰的函数
            self.routes[(method, path)] = func         # 登记！函数本身没被改动
            print(f"[注册] {method} {path} -> {func.__name__}")
            return func                                # 原样返回
        return decorator

    def handle(self, method, path):                   # 模拟"来了一个请求"
        func = self.routes.get((method, path))
        if func is None:
            return 404, "not found"
        return 200, func()


app = MiniApp()


@app.route("/posts")                  # 两步展开：
def list_posts():                     #   decorator = app.route("/posts")
    return "帖子列表"                  #   list_posts = decorator(list_posts)


@app.route("/posts", method="POST")
def create_post():
    return "已创建"


if __name__ == "__main__":
    print("--- 上面两行 [注册] 是在 import 阶段就打印的，此刻我还没调用任何函数 ---")
    print(app.routes)
    print(app.handle("GET", "/posts"))
    print(app.handle("POST", "/posts"))
    print(app.handle("GET", "/nope"))
    print(greet())
```
