## 4. 后续重写必须沿用的教学决定

### 4.1 路线与负荷

- 一课一个核心解释目标；先正确实现，再分析已知缺陷，不以多个复杂故障同时开场。
- 第一个正例后，学生作一次小决定：固定契约下选择实现方式、测试输入或情境分类；不自由增改公开 API。
- 常规课 95 分钟教学＋5 分钟缓冲；第 6／11／15 课为 80 教学＋15 小测＋5 缓冲。不能把小测偷偷挤进 95 分钟。
- 预测题给全初值、操作次序、环境、唯一变化与没有发生的其他变化；先预测，再揭晓。运行依赖安装不是预测题。
- 每课一张常用写法卡、一个作业包；已有课堂证据复用，不额外堆叠审计报告、扫描器、固定抓错率或性能指标。
- 每份模板标明“要求解释／要求会用／黑盒”。黑盒内部不进口试、不要求学生修改，也不把教师设施开发转嫁给学生。
- AI 正确解释允许直接接受并说明依据。预制错误标为教师构造，不冒充真实 AI 输出。
- 第 10／11 课前端 AI 为解释器；第 12 课用一段已知竞态样本进入修复与验证，不提前做整套 React 最佳实践评审。

### 4.2 材料归属

底稿按教学单元组织，不先按幻灯片页数切割。正文保留学生理解需要的条件、任务、原因与边界；复杂配置、完整参考和教师工具放附录，交接与验证状态可单列章节，不强制统一表格。

制作最终 Slidev 时，学生“理解什么、做什么、依据什么”留正文；教师“怎么讲、讲多久、失败后如何切换”进备注。参考层不等于可以删掉必要的正确性与安全边界。

目前新版第 1–11 课仍标注未归档。开始正式工程移交后按 authoring-workflow 冻结底稿，后续改动进入最终工程，不在多个副本里互相覆盖。

### 4.3 已确定的前端分工

- 第 10 课解释源码到浏览器的链路；React 状态与 GET 适配器内部为黑盒。课程包有真实 M3 GET 联调要求，不能说所有 HTTP 都留到第 12 课才出现。
- 第 11 课只对本地固定列表和表单 UI 做交互；练习 author 不进入公开 API；不发业务请求。
- 第 12 课系统讲 Effect／请求生命周期／Query／真实创建反馈。
- 第 13 课讲 Router、URL 可恢复查询与状态归属，完成 M4。
- 第 16 课处理完整 CORS、部署和流式累积首次需要的最小函数式更新。
- 完整状态更新队列、批处理与并发渲染仍是参考层，不承诺第 12 课“还完整队列债”。

## 5. 当前主线契约：接第 12 课时不要改错

此节描述第 8–11 课交给下一课的现行基线，不把后期增量倒灌到第 1–5 课历史阶段。详细模型、路由和边界以第 3／4／6／7／8／9 课正文及附录为准。

### 5.1 路径、字段与校验

| 项目 | 现行约定 |
|---|---|
| 列表 | `GET /questions?keyword=&page=1&page_size=20`；默认空关键词／1／20；page ≥ 1，page_size 1–50 |
| 搜索／分页 | keyword 先 strip；标题或正文的字面子串，`%`／`_` 不当通配符；按 id DESC 后分页；total 为过滤后、分页前总数 |
| 列表输出 | `items/total/page`；每项 `id/title/body/tags/created_at` 五字段 |
| 详情 | `GET /questions/{qid}`；qid 只整数解析，不加 ge=1；不存在的 0／负整数也是 404，非整数为 422 |
| 创建 | `POST /questions`；只接 title/body/tags，拒绝额外输入；201＋Location |
| title/body | 先 strip，再检查 5–200／10–20000；清洗后的标题精确重复为已知 409 |
| tags | 默认 []；原列表最多五项，先验数量，再精确去重保留首次顺序；不 trim、不排序；六个重复标签仍非法 |
| 第 8 课增量 | vote_count 默认 0、version 默认 1；详情／创建／PATCH 为原五字段＋vote_count/version，共七字段；列表仍五字段 |
| 投票 | `POST /questions/{qid}/votes`；以旧 version 条件写入；成功 200，返回 `qid/vote_count/version` |
| PATCH | `PATCH /questions/{qid}`，自定义 JSON 部分更新；version 必填且严格正整数，title/body 至少一个；省略保持，显式 null 拒绝 |
| 并发 | 投票与 PATCH 共用行版本；冲突不自动获取新版本再重发 |
| 禁止擅加 | author、answer_count、sort/status、`/api` 前缀或不同的公开参数名；若未来批准变更，明确登记并同步消费者 |

第 11 课表单原文保留，tags 固定 []。即时提示用 JS trim＋码点计数，但不是后端 Python strip 的完整替代；不靠 disabled 或前端校验保障服务端安全。

### 5.2 错误、表现与提交

- 普通 JSON 错误为 `code/message/detail/request_id`；422 的 detail 为 `loc/type/msg` 列表。
- 404：question_not_found；409：version_conflict 或已识别标题约束的 duplicate_title；422：validation_error；未知数据库／基础设施错误走安全 500。
- 响应 X-Request-ID 与错误正文 request_id 一致。JSON 路径不因 Accept:text/html 自动变成 HTML。
- HTML 三页继续保留：失败原文回填、成功 303、自动转义。探针独立使用单 status：200 ok／预期数据库故障 503 degraded，不套普通业务错误体。
- 服务用例入口拥有事务并显式 commit；辅助数据函数不各自提交；依赖只提供／关闭资源，不在 yield 退出提交。
- 成功响应晚于提交确认。真实提交证据用独立连接回读，不能用外层统一回滚测试声称提交已验。

| 教师故障注入位置 | 响应与数据结果 | 边界 |
|---|---|---|
| flush／写入完成，commit 未调用 | 500；本次写入回滚 | 已执行 SQL 不等于已提交 |
| commit 已确认成功，响应尚未启动 | 500；本次写入仍在 | 之后 rollback 撤销不了已提交结果 |
| 提交确认丢失等真实断连 | 结果可能未知 | 上述两开关没有模拟此类故障；不能据 500／超时直接判未写或自动重试 |

### 5.3 模型、迁移与门禁

- 五表与第 6 课 DDL 一致；外键采用既定默认限制策略，不擅加 ON DELETE CASCADE。
- 第 7 课 M2 迁移从空库执行 `001_baseline` 到 head；第 8 课增加 `002_question_version`。当前完整链为 001→002，body 列名不改，不恢复旧稿的正文列改名任务。
- 第 7 课 N+1 的 21／2 SELECT 依赖固定 20 问题与给定加载场景，不是所有列表恒定查询数。公开 DTO、total 查询、空页需分别计数。
- 第 9 课统一四类门禁：lint/type/test/contract。第 10 课增加 web lint、check、build，all 从六条分发命令扩至九条，首错停止；保留原 contract-client 和后端回归。
- `npm --prefix web run verify` 不替代含后端的 all。分发替身、YAML 静态核对不证明远端 CI 执行，更不证明分支保护已强制生效。

### 6.3 必须写全并验证的条件

- 竞态示例 A／B 从发起到正常返回分别 800ms／200ms，两次点击间隔 100ms；无保护时每次响应写当前详情。固定初始选择、点击次序和故障模式，再预测无保护／有保护结果。
- 使用 AbortController 后，通过服务日志观察收到几次请求、执行到哪里；不从客户端取消次数推断服务器停止，更不能推断写入回滚。
- Query 至少固定 staleTime、refetchOnWindowFocus，明确其他自动重取／重试设置、缓存起点和观测窗口。同一个 QueryClient、固定其他参数，先测遗漏 keyword，再清空实验缓存并补全 key；不无条件承诺第二次搜索一定发请求。
- queryKey 包含全部影响结果的参数。缓存条目数量与最终 UI 分别验，教师答案标注依赖给定配置。
- HTTP 非成功响应须由适配器转为 reject；保留四字段错误、request-id 与 422 detail，409 按 code 处理，不把所有非 2xx 都叫网络失败。
- 创建成功要失效相关数据并回读；失败保留输入。写请求超时／断连可能结果未知，不能自动重放。
- 必测正常／空／加载／错误、受控过期结果、修复后结果、Query key 隔离、创建成功回读、422／409 和未知结果边界。只跑类型或构建不能代替这些行为验证。
- 不借本课提前加入 Router／URL 状态管理、完整 CORS、全套更新队列或性能专题。

完成后更新第 11 课 §8.2 中“旧第 12 课待重写”的状态，保留第 11 课历史实测与未验收项。第 13 课只读取作交接检查，不未经请求整课重写。

### 6.4 更后续的方向

第 13 课负责 URL 可恢复状态和 M4；第 14 课先跑正确会话与授权流程，模板同时带 SSR 同步器 token 和 SPA 强制自定义头等 CSRF 基线，写测试 fixture 随认证升级。
