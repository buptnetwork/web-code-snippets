## 1. 接手后先做什么

1. 阅读本说明，明确哪些已完成、哪些需要新团队开发。
2. 阅读技术说明第 3～8 节，优先对齐角色 Cookie、JSON 格式、教师接口和 SSE。
3. 确认第 9 节学生接口建议并生成首版 OpenAPI；在新仓库提交迁移、配置样例和可复现启动说明。
4. 先实现“教师登录 → 创建课堂 → state → SSE → 结束”的纵向链路，再接学生投稿、活动和审核。
5. 按本说明进行真实三端联调、权限负向测试、容量与故障验收；完成前不作为正式课堂服务上线。

编写本说明时，课件实现与这些文档尚未形成对应提交或发布标签，工作区有未提交及未跟踪文件。不能只发送仓库 HEAD 或两个 Markdown 就假定对方已获得完整实现；实际交付前由负责人确认源码包/分支包含第 3 节文件，并记录双方基线提交号。第 10 节提供签收表，人员、环境和版本信息由团队补齐。

- 单窗口教师面板可被投影观众看见。真实敏感审核建议使用独立展示窗口，最好独立浏览器配置文件验证角色隔离。

## 6. 本地联调操作

### 6.1 三个进程与配置

建议本机端口：后端 8000、学生 Vite 5173、Slidev 3030。后端暴露完整 `/classroom-api/v1`；学生 Vite 使用 `base: '/classroom/'`，其 `/classroom-api/` 也代理到后端。

后端需配置实际浏览器 origin 白名单。`http://localhost:3030`、`http://127.0.0.1:3030` 和局域网 IP 是不同 origin，不要混用导致 Cookie/Origin 校验失败。本地 HTTP 可仅在开发配置关闭 Secure，生产禁止沿用。

新项目尚未创建，后端/学生实际安装与启动命令由团队提供；例如采用 `app.main:app` 时，在 backend 目录运行单 worker Uvicorn，但不能把此示例当作当前已有脚本。

在当前课件仓库执行：

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
VITE_CLASSROOM_ENABLED=true \
CLASSROOM_API_PROXY=http://127.0.0.1:8000 \
CLASSROOM_STUDENT_PROXY=http://127.0.0.1:5173 \
pnpm exec slidev ch00.md --port 3030
```

打开 `http://localhost:3030/`。VITE_ 变量是公开构建配置，可放 `.env.local`；两个 CLASSROOM_*_PROXY 由启动进程环境读取，不从 `.env.local` 自动加载。不能将密码或凭证写入这些变量。代理改动需重启，静态产物不含开发代理。

### 6.2 首次真实联调脚本

1. 使用后端运维命令创建测试教师，凭据通过安全渠道交付，不写入本文、Git 或截图。
2. 打开 ch00，DevTools 过滤 `/classroom-api/`：无请求。已有教师 Cookie/恢复记录时重复此检查。
3. 点“互动”：仍无 API。点教师入口：GET me（未登录 401）；登录成功后仅有课堂列表，没有 SSE。
4. 创建课堂：POST sessions 含 Idempotency-Key → GET state → 一条 events；核对元数据 `courseId=web-development-2026b, deckId=ch00`。
5. 显示二维码，链接为当前 origin + `/classroom/join/{8位码}`。学生确认加入后才 POST join、建立一条学生 SSE。
6. 新建并开启 choice，学生提交/改票；教师看实时统计，学生/展示响应没有统计与答案。关闭 → 公开统计 → 揭晓答案，逐步核对网络返回。
7. 新建并开启 text，学生投稿 pending → 教师允许展示 → 精选 → 隐藏，核对公开墙与私有列表。
8. 另一浏览器配置文件打开同章，兑换 10 位配对码；教师操作实时同步。8 位加入码不能用于展示授权，重复兑换同码失败。
9. 收起/重开/翻页 SSE 仍各一条；退出本窗口只关闭其连接，另两端继续。撤销展示授权仅影响相应展示连接。
10. 结束课堂前首次点击只出现确认；确认后停止投稿、发送完整终态、各端关闭 SSE。刷新读取有效授权下最终 state，不创建新课堂。
11. 在 ch01 重复入口和路径检查，deckId 为 ch01；拿 ch00 绑定连接应提示课件不匹配。

### 6.3 手机与生产路径验证

手机不能扫码访问教师电脑的 localhost。应从手机可达的局域网 origin 打开课件，让二维码自然生成该 origin；后端白名单与代理也必须对应。HTTP 局域网下复制链接可能受安全上下文限制，二维码和可见 URL 仍应可用。

优先使用局域网同源反向代理。若使用 Slidev `--remote` 开放监听，注意该开关同时启用 Slidev 远程控制，应设置控制密码、限制可信局域网，测试结束关闭；它与教师业务认证无关，不要无保护暴露到公网。具体开关以 `pnpm exec slidev --help` 为准。

生产路径需构建并使用有 SPA fallback 的静态服务器/反向代理验证：

```bash
VITE_CLASSROOM_ENABLED=true pnpm build
```

重点覆盖 `/web-2026b/ch00/`、`/web-2026b/ch01/` 以及学生直接刷新 `/classroom/join/...`、`/classroom/session/...`。两个课件章节都必须请求根路径 `/classroom-api/v1`，不能变成 `/web-2026b/ch00/classroom-api/...`。

## 7. 生产接入与运行交接

### 7.1 nginx 路径模板

下列片段是供部署团队调整的模板，不是已应用配置。假设后端仅在本机 8000 监听，保留完整路径，并托管已构建学生 SPA；应加入现有 HTTPS server 块，保留已有证书、安全头和课件静态配置。

```nginx
location ^~ /classroom-api/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 90s;
    gzip off;
}

location ^~ /classroom/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    # 避免记录带加入码的学生 URL；按需改为经过脱敏的日志。
    access_log off;
    add_header Referrer-Policy no-referrer always;
}
```

注意事项：

- proxy_pass 没有尾部 URI，原路径保留。后端 student fallback 必须限制在 `/classroom/` 内。
- API 应用返回 no-store，SSE 另返回 X-Accel-Buffering:no；若还有 CDN/上游代理，也需验证真实流式穿透。模板为简化统一关闭 API 缓冲，可在验收后细分 SSE 路径。
- 模板假设 nginx 是公网入口；多级代理需要重新配置可信链，不直接信任任意客户端 X-Forwarded-For。后端只信任受控代理。
- 核对全局 error_page 不把 API 401/404/5xx 转成 HTML 或 SPA；应用异常统一 JSON。外层网关错误需有明确降级提示。
- nginx add_header 的继承规则可能影响现有安全头，部署时检查完整配置，不能只复制片段即视为验收通过。
- 静态 Netlify/Vercel 配置不会自动提供上述后端。更换托管方案须另验 SSE、Cookie、超时和来源约束。

## 8. 联合验收清单

以下全部是完整系统待验收项，不因课件已有 47 个测试而自动通过。测试数据用临时课堂，证据脱敏记录到新项目测试报告。

### 8.1 功能与协议

- [ ] login/me、分页、创建、配对、审核返回对象满足技术说明；null/[] 不省略，无 data 包裹，无尾斜杠跳转。
- [ ] SSE 初帧在 15 秒以内，使用命名完整快照；正常结束不是仅发 ID，重连从数据库恢复。
- [ ] 相同创建键和正文仅一个资源，异正文 409；选择题重复 PUT 不增票；文本同 ID 不增条。
- [ ] 草稿/开题/关题/复制、投票/单选/多选/文本全部通过；最多一个开放题、5 条文本、3 条精选约束并发下有效。
- [ ] publication 部分 PATCH 保留已有 true；统计和答案分步公开；隐藏投影不撤销学生已公开结果。
- [ ] 切题迟到提交不写错题；关题并发结果由事务顺序决定；超时未知结果可恢复。
- [ ] 分页加载和刷新无格式问题，currentActivity/results/comments 始终相互对应。

### 8.2 安全与浏览器

- [ ] 访客、学生、展示均不能管理；教师 A 不能访问 B；改 sid/aid/rid/view 不能越权。
- [ ] 教师/展示/学生 Cookie 同时存在时仍按请求角色过滤；从 HTTP/SSE 原始响应确认未泄露答案、待审核正文或身份。
- [ ] 8 位加入码/10 位配对码分离，配对单次兑换、过期、撤销；注销只撤销对应教师会话。
- [ ] 跨站写、缺失/错误 Origin、表单提交被拒绝；合法同源 GET 没有 Origin 时仍可读取。
- [ ] 公开课件在无 Cookie/有 Cookie/有恢复记录时均零互动请求，打开面板仍不连网。
- [ ] 双窗口真实同步；收起/翻页不增连接；退出、结束、pagehide、卸载清理；前台恢复重新校验。
- [ ] 手机 Safari、Chrome、课堂扫码内置浏览器验证；不兼容时提示系统浏览器，说明 Cookie 不共享。
- [ ] 真实键盘空格/方向键/Esc 和焦点恢复复验；实际导出文件不带互动浮层、不发业务请求。
- [ ] 恶意 HTML/脚本文本只显示文本；日志、错误报告与 Referer 不泄露密码、Cookie、配对码或投稿正文。

### 8.3 容量与故障

- [ ] 3 课堂 ×（100 学生 + 1 教师 + 1 展示）≈306 SSE，保持至少 60 分钟。
- [ ] 300 学生 5 秒内提交，选择、改票、文本多轮压测；数据库记录与成功回执/去重统计一致。
- [ ] 稳定提交 API p95 ≤1 秒，集中提交 p95 ≤3 秒，应公开的变更到展示 p95 ≤2 秒。
- [ ] 记录服务器规格、网络、软件版本、负载脚本与原始指标；无持续锁失败、无界队列或连接泄漏。
- [ ] 服务重启、全体重连、慢消费者、断网、429/503、权限撤销均不产生重复课堂或丢失已确认回答。
- [ ] 叠加 500 次普通课件访问不增加身份请求/SSE；共享校园 NAT 不被按 IP 连接上限误伤。
- [ ] 在线备份实际恢复成功，迁移失败有可执行恢复方案。

| 现象 | 首先核对 |
|---|---|
| 没有“互动”入口 | enabled 是否严格 true、重启/重建、章节四字段、是否在播放场景 |
| 打开面板没有 API/SSE | 正常延迟行为；需点击教师入口并明确连接课堂 |
| 404 或“未返回 JSON” | 后端是否存在、代理目标、API 是否落入静态 fallback |
| 网络失败但后端记录 307 | FastAPI 尾斜杠重定向；当前 fetch 禁止 redirect |
| 登录 200 但后续 401 | Cookie Path/同源、HTTP 开发是否误设 Secure、是否切换 localhost/IP |
| 422 只有笼统错误 | 是否仍返回 FastAPI detail 而非 code/message/requestId |
| 已连 SSE 却每 15 秒重试 | 初帧是否命名 snapshot、是否完整合法 JSON、是否被代理缓冲 |
| 只推心跳不更新/另一窗口不更新 | 单 worker 约束、提交后广播、订阅角色、合并任务、代理缓冲 |
| 提示课件不匹配 | courseId + deckId，不根据名称相近或页码绕过校验 |
| 手机二维码打不开 | QR 是否为 localhost、局域网路由/监听/防火墙、学生 base/fallback |
| 未公开结果出现在网络响应 | 后端白名单缺失；优先修服务器，不能仅改 UI 隐藏 |
| 结束后反复重连 | state 是否仍能返回授权终态、ended 事件是否完整，events 204 是否与 state 一致 |

## 10. 签收与变更记录要求

正式交接时由双方填写以下信息，不将未完成项默认为已验收：

| 项目 | 待填写内容 |
|---|---|
| 课件基线 | 源码交付方式、分支/提交号、文档版本 |
| 新项目基线 | 仓库地址、提交号、OpenAPI 文件位置与版本 |
| 人员 | 后端、学生端、课件、测试、部署负责人及协作渠道 |
| 环境 | 开发/验收/生产 origin、路径、实际启动命令；秘密另行安全交付 |
| 契约确认 | 学生建议字段、错误码、分页排序、健康路径及所有与基线差异 |
| 验收结论 | 报告链接、已通过项目、未完成事项、责任人与处理期限 |
| 上线批准 | 日期、维护窗口、回退负责人；容量和安全验收结论 |

后端契约变更先提供请求/响应样例、兼容影响与测试，再由课件方决定是否同步发布。本文不代表已部署或批准上线；生产变更以联合验收和责任人签收为准。
