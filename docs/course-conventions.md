# 当前课程约定：现代Web开发技术

> 本文说明当前《现代Web开发技术》课件工程的目录、素材、视觉、示例与教学准确性检查约定，不是所有软件类课程的统一模板。
> 制作职责与内容所有权遵循[通用流程](authoring-workflow.md)，具体语法和验证方法见[Slidev 实施指南](slidev-authoring-guide.md)。运行和部署命令以[README](../README.md)为准。

## 1. 工程与教学材料映射

全课程共用一个 Slidev 项目，每章一个入口，章内通常按次课拆分。当前入口使用 seriph 主题，具体设置以文件为准。

| 内容 | 当前路径 / 约定 |
|---|---|
| 章节入口 | 根目录 `chXX.md`，如 [ch00.md](../ch00.md)、[ch01.md](../ch01.md) |
| 次课内容 | `pages/chXX/*.md`，入口通过 `src:` 引入 |
| 可运行示例 | `snippets/chXX/`；多文件实现保留自己的子目录 |
| 共用组件 / 布局 | 根目录 `components/`、`layouts/` 等 Slidev 约定目录 |
| 位图 / 图示 | `public/images/`、`public/diagrams/`；`common/` 放全课共用素材，`chXX/` 放章节专属素材 |
| 其他资源 | `public/videos/`、`public/fonts/` |
| 教学底稿 | `docs/draft/`；已移交的底稿必须标注归档及对应成稿位置，文件在此目录不代表已归档 |

根目录入口便于本工程解析共享组件与资源，也是当前构建脚本扫描章节的约定。迁移其他课程可另定组织方式，不把 `chXX` 作为通用教学格式。

新增章节按现有入口与次课组织接入；新增章节的部署路由要求见 README。制作或验收某次课时，须确认对应 `src:` 未被注释，不以章节入口存在代替实际内容覆盖。

## 2. 章节封面与机构标识

### 已登记版式：章节封面

该版式已在 ch00、ch01 使用。新增章节参照 [ch00.md](../ch00.md) 首屏，沿用 seriph 的 `cover` 布局效果：

- headmatter 使用 `background: /images/common/jr-korpa-3XXSKa4jKaM-unsplash.jpg`，全课共用本地背景，不依赖主题的随机远程 Unsplash 占位源；该远程源在历史制作中曾失效。
- 标题上方居中放置 `/images/common/combination_mark_logo.png`，保留 `invert brightness-0` 反白，避免深蓝标志在暗色背景上不可读。
- 标题、副标题和按键提示沿用已有结构，只替换本章内容。当前封面布局对背景叠加暗色渐变并使文字变白，无需在各标题重复设置。

这不是任意布局均支持背景的保证。按当前主题约定，`cover` 消费 `background`；`section`、`default`、`center`、`full` 不因设置这个字段就自动铺底。新增正文背景或更换主题需核查实际布局实现并预览。

### 正文徽标

[slide-bottom.vue](../slide-bottom.vue)统一提供右上角校徽：资源为 `/images/common/bupt_logo.png`，尺寸 36px，普通模式 `opacity-40`、深色模式 `dark:opacity-70`。

`cover` 与 `full` 自动排除；正文页不要重复放置机构标识。以上背景、组合标志和校徽只属于当前课程视觉身份，迁移新课程时不得默认沿用。

## 3. 可复用参考与代码资产

### 版式参考

- [导论成稿](../pages/ch00/00-lecture-zero.md)可参考居中表达、分隔页和整屏表达，但不是固定页型清单；其中未同步的旧教学路线不构成 v4 要求。

常规页求同类一致，重要表达按教学需要单独设计。版式登记和组件化时机遵循通用流程；此处不预先增加完整布局库。

第一课可按标题定位以下参考，避免依赖插页后会变化的页码：

| 参考标题（均在docs/slides-samples.md中） | 可复用的表达 |
|---|---|
| 四个基本概念，一张成绩表就讲明白 | 定义与同一份数据实例逐项对应 |
| 同一个逻辑结构，两种内存映像；引用：一格两标签 | 左右对照、内存格与标签；延续青 / 橙配色时保持同一对象的语义一致 |
| 四种形参形式，以后写每个接口都回来查 | 接口代码与选择依据配对；当前局部代码字号 16px、行高 24px 可作试排起点，不是全课硬性标准 |

参考的是表达方式，不代表这些页面的全部表述已经校正。复用调试器截图时按实施指南放大关键证据；复用“六类内存错误，一行代码看一个病”等密集表格时，特别核对表后说明与底部图示是否可见。

### 当前代码组织

- 第1课当前包为 `snippets/ch01/first-api/`，独立 pyproject／uv.lock／Python 3.12 环境，起始、练习、参考均为各自目录的 `main:app`。不使用 reload，修改后重启；启动与调试见 [snippets 说明](../snippets/README.md)。
- 正文引用源码 region；内联教学阶段节选保持同一契约，分级提示先于完整参考。固定数据只有 id/title/body 三字段，M0 不含数据库、搜索分页或 request-id。
- `check_m0.py` 是标准库 HTTP 黑盒；教师实验与 `verify_examples.py` 不转化为学生实现任务。第二课教师增量包尚未制作。
- `snippets/ch01/m0-tracer/` 和旧取证素材保留历史用途，不移动、不作为新第一课的起点或验收器。
- 第一课正文以显式 `class: l01` 限定样式；五框图组件为 `FirstRequestFlow.vue`，不修改旧八环节组件语义，也不为未来整章默认套用第一课样式。


## 4. 迁移到另一门课程

复用通用流程和适用的 Slidev 指南，在目标工程改写本文件的课程约定。无需新建课程配置格式，也不必复制旧课件或历史底稿。

AI 先读目标工程的 README、依赖、入口和已有示例，整理已知条件；教师只需用自然语言确认教学偏好与例外：

- 学习者的基础、课程目标及本次课的范围。
- 已选技术栈、依赖版本和实验环境；尚未选定的关键项明确待确认。
- 网页、PDF、现场演示等交付要求，网络条件、初始状态、复位和备用方案。
- 文件组织与视觉身份，包括是否保留章节入口、示例放在哪里、使用何种标识。

迁移说明示例（**待在目标课程验证，不是本仓库配置或已存在的工程**）：

> “现代 Web 开发技术”面向已掌握基础编程与 HTML/CSS 的学生。本次课讲异步请求和界面状态，不预设具体框架，由课程已有项目确定。完整演示保留前后端文件、依赖锁文件和测试数据，课件只展示关键链路；工程放独立目录或独立仓库并固定版本，不强制使用 snippets。课堂使用本地隔离数据，能复位并模拟成功与失败；断网时使用已核对的录屏或截图。视觉和标识由新课程确定。

框架、版本、启动方式等若目标项目尚无依据，AI 只整理需要决定的事项，不擅自选成新的课程要求。真实凭据和生产数据不进入演示工程。

### 迁移走读

| 场景 | 保持不变的流程 | 只需补充的课程条件 |
|---|---|---|
| 单文件算法讲解 | 审读、关键表达验样、分批成稿、分层验收、就地修改 | 语言与编译条件、测试输入和预期结果、代码引用及高亮 |
| 多文件 Web 请求与界面演示 | 同上，不修改通用流程 | 前后端启动与依赖、请求/响应、界面状态、复位、网络及静态备用材料 |

两种场景的写作范例见[教师指南](lesson-draft-guide.md)。这里是文档适用性走读，不代替代码运行、浏览器检查或课堂实测；跨课程端到端效果仍待实际验证。
