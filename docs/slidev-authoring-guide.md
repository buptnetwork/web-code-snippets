# Slidev 课件实施指南

> **读者**：负责制作与维护的 AI 或开发者。先读[通用制作流程](authoring-workflow.md)，再结合[当前课程约定](course-conventions.md)执行；教师只需[底稿指南](lesson-draft-guide.md)。
> 本文是操作指南，不是验证报告。历史实测基线为 Slidev v52.19，见[旧版快照](history/authoring-workflow-legacy.md)；版本性行为以目标工程的实际检查为准，更新规范不代表已有课件通过验收。

## 1. 确认环境与验证入口

先读取项目 README、入口文件、依赖与锁文件，确认主题、实际安装版本、交付格式和目标次课的引入关系。不要将某个课程的命名或版本当成 Slidev 的普遍要求。

- 确认目标页面已通过 `src:` 等方式进入实际预览与构建入口，注释掉的次课不算覆盖。
- 页面拆分和静态资源路径按本项目约定处理；不能把章内文件作为独立入口后，默认共享组件与主题仍相同。
- 安装版本、主题或浏览器变更后，重新验证代码引用、关键动画、滚动与导出行为。
- 本仓库现有运行和部署命令以[README](../README.md)为准。[package.json](../package.json)目前未提供统一的课件检查命令，也未声明 `playwright-chromium`；不能声称已有一键验收能力。

## 2. 分页、教学定位与备注

AI 通读完整次课，先给“教学单元 → 页面 / 演示”的简短对应，再把关键表达与常规页分批写进同一最终工程。正文保留学生理解与复习所需的定义、核心解释、证据、结论和必要条件；备注补充口语展开、节奏与操作提醒，不默认把详细内容全部移出正文。

稳定编号可保留在页面标题或备注首行。一个单元跨多页时，保留共同编号和各页角色；定位时结合文件、编号、标题，不依赖易变的页码或行号。口语化标题可保留，但需能从标题、副标题或单元导航中识别知识主题，便于课后检索。

```markdown
<!--
教学单元：web-request-state（请求与界面状态）；本页：观察 HTTP 错误。
先展示页面提示，再定位 Network 中对应的请求。

[click] 对照 Network 的状态码，解释为什么“有响应”不等于“成功”。
-->
```

这是备注示例，其中的单元标识由 AI 维护，不是需要教师填写或程序解析的底稿格式。备注放在对应 slide 末尾；`[click]` 用于演讲者视图的进度同步，必须和页面实际点击步骤核对。

- 分步揭示服务解释顺序，如先观察证据、再说明原因；确有预测或提问意图时才安排答案揭示，不默认增加互动。
- 删除、移动或重做页面时，同时核对备注、问题、答案和前后呼应。
- 单个连续算法可同页滚动；前后端协作或调试可按阶段分页，保留文件标签、链路位置和必要上下文。
- 不用缩到不可读的字号或裁切内容来满足“不溢出”。

## 3. 代码与项目引用

### 独立来源与 region

可运行示例的权威来源在独立文件或可定位版本的项目中；这里的 `snippets/` 只是引用示例，不是其他课程必须采用的目录。

[现有 TypeScript 示例](../snippets/external.ts)使用 VS Code 风格的 region 注释：

```ts
// #region snippet
// 需要展示的代码放在这里
// #endregion snippet
```

对应引用可以叠加 region、行号、高亮与滚动高度：

```markdown
<<< @/snippets/external.ts#snippet {all|2-4|all}{lines:true,maxHeight:'300px'}
```

`@` 指向包根目录。以上高亮对应现有示例的 region，源码变化后仍需检查；只引用完整文件时可省略 region。不支持注释的文件格式不要为了加标记而破坏语法。

- 本项目历史实测确认 `.c` 文件的 `// #region name` 能被识别，参见[算法分析代码](../snippets/ch01/algorithm-analysis.c)。这不是对所有语言注释写法的保证。
- 构建后核查展示范围，避免测试入口、标记行或无关代码混入讲解。
- 行高亮使用 **region 内相对行号**；增删代码可能不报错却高亮错行。优先采用有语义的 region，仍要检查其内部高亮。
- 修改源码时检查所有引用页和内联简化版。多个阶段版本要标明用途和与最终实现的关系。
- 多文件 Web 项目可以保留自己的依赖、配置和启动方式，课件只引用必要片段，不把完整应用改造成一个孤立 snippet。
- 外部项目记录仓库、具体文件和提交或发布版本；引用不能只指向会变化的默认分支。必要的本地镜像应注明来源，不作为第二份独立维护的实现。

### 滚动与代码演变

`maxHeight` 可与逐步高亮组合；高度按当前版式验证，示例中的数值不是通用常量。

历史实测在 v52.19 观察到高亮行自动滚入可见区域，但原记录未找到官方行为承诺。不能据此保证新版本或所有布局也成立，升级后需逐步点击复测。

现有技术基线下，magic-move 使用多个内联围栏代码块，不支持把 `<<<` 导入直接当作演变步骤。可用内联简化版表达变化，最终完整实现仍引用独立来源；交付前核对两者一致性。

可执行的故障示例仍须验证预期失败，不能因它“故意错误”就跳过检查。无法执行的伪代码或短说明片段可直接内联。

## 4. 图示、资源与样式

具体视觉身份由课程约定决定；优先参考已完成页面，先复用样例，稳定后再组件化。

### 内容详实型页面的视觉基线

- **三层信息**：主结论 → 解释与证据 → 条件与补充。靠位置、间距、字号和适度强调区分层级，避免全页等重或到处加框；核心条件也要可读，不能藏进低对比度小字。
- **稳定阅读尺度**：同类正文、代码、图注采用一致字号和行距；源码、命令、输出与图中标签都是教学正文，不能只保证标题清楚。按实际画布、主题与投影条件验证，不照搬某页的像素值作全局标准。
- **布局先于缩字**：先预留标题、导航、徽标和底部安全空间，再安排主体。内容过密时调整分栏、分组或增加承接页；禁止用整体缩放、缩小字号或隐藏溢出来掩盖内容缺失。
- **对齐与留白**：同类页保持标题基线、栏间距、代码框和图注位置一致；留白用于分组。图或代码过小而旁边空白充足时，先扩大有效内容，不额外添加装饰填空。
- **颜色有语义**：同一对象、状态和关系在跨页图示中保持一致；错误与警告有固定区别，并配文字、线型或符号，不能仅靠颜色表达。

以下是按内容选用的参考版式，不是每课必须配齐的模板：

| 表达类型 | 组织重点 |
|---|---|
| 概念 + 实例 | 定义与实例逐项对应，必要时标注示例数据为节选 |
| 并列对照 | 使用同一尺度、相同数据和对齐位置，只突出真正差异 |
| 代码 + 状态变化 | 代码、当前步骤、对象或界面变化同步；连续调用要说明状态是否重置 |
| 证据 + 解释 | 放大关键截图区域，配对应标记和由证据得到的结论 |
| 分类速查表 | 列名直接表达比较维度，单元格易扫读，条件与末行完整可见 |

### 图示与截图的教学加工

- 图中结点、箭头、线宽和标签采用一致尺度；放大 Mermaid 等图表时一起检查标签，不让图成为四周留白中的小缩略图。
- 地址、内存格、请求箭头等示意表达注明必要假设；语义图不冒充真实布局，实测截图不冒充语言或协议保证。
- 截图先确定“学生要看哪处、据此得出什么结论”，再组织为环境概览（需要时）+ 关键区域放大 + 对应解释。裁切不能丢掉理解所需的上下文，也不能改变原始证据。
- 用编号、框选或同色标记连接字段、字节、状态与解释；保留原始素材，检查放大后的清晰度，并遮盖敏感信息。关键区域无法辨读时重新采集，不把插值放大当作恢复细节。

### 资源与图示实现

本项目静态资源放在 `public/`，课件使用以 `/` 开头、相对于 public 根的路径。frontmatter 的 `background:` / `image:` 不经普通 Markdown 资源转换，应按该约定填写；部署到子路径后仍要检查实际加载结果。

使用可随导出保持清晰的图示形式，并分别检查网页和 PDF。结构性图示在当前 UnoCSS 环境优先用 HTML + 工具类，曲线、多边形等几何内容用 SVG；适合关系描述时可用 Mermaid。技术选型不要求教师指定。

### 当前 attributify 环境的 SVG 注意事项

历史实测记录过属性被 UnoCSS 误当作工具类的情况。当前项目继续采用以下避坑写法，换环境后按实际渲染验证，不推广为 SVG 标准本身的限制：

- 不写 `font-size="12"`，改成 `style="font-size:12px"`。旧环境曾将前者改成约 `3rem`，导致文字过大并被裁掉。
- `<text>` 不依赖默认填充或 `fill="currentColor"`，也不加 `opacity=`；使用明确颜色，如 `fill="rgb(71,85,105)"`。旧组合曾出现文字不显示。
- 图示字体、边界、颜色与对比度须实看；源码正确、截图四边干净都不能证明文字可读。

背景只有在布局消费 `background` prop 时才有效，不能推断所有布局都支持。当前 seriph 封面及徽标规则见[课程约定](course-conventions.md)。

## 5. 预览与渲染检查

按照通用流程分层验收；这里补充 Slidev 的实现检查，不能替代教学内容审读。

1. 启动包含目标次课的预览入口，确认页面标题和内容范围；记录实际版本、主题、浏览器及视口。
2. 等待字体、图片、图表和代码渲染完成，再检查当前可见 slide。空白、加载中或缺资源截图应判为异常。
3. 普通页检查初始与最终状态；有点击、代码演变、滚动或交互的重点页逐步检查关键状态；仅在设计了先问后答时确认答案没有提前暴露。
4. 结合截图、可见页 DOM 边界与滚动容器检查裁切和遮挡，并对照源码核对末行、底部结论和图注是否实际显示。区分尚未揭示、被遮挡与真实溢出；四边像素检查不能证明容器内部完整。
5. 按视觉基线实看正文、代码、图中标签、命令和截图证据的阅读尺度与对比度。没有溢出不等于可读，不能只在浏览器放大后验收；普通屏幕预览不能冒充教室投影实测。
6. 修改后按影响范围重检；共享样式、布局或组件变化要覆盖它们的使用页。

### 历史截图方案的适用边界

旧 ch00 实测因缺少导出依赖，曾用 dev server + Playwright 缓存中的 Chrome for Testing，以 `--headless --screenshot` 截取 `?clicks=999` 页面并检测边界像素。

该记录说明曾有可用的替代路径，不意味着新机器有同样的缓存。`?clicks=999` 也只覆盖最终点击状态，不能覆盖已消失的中间内容、交互输入或长代码的全部滚动区域。

旧环境中非可见页的缩放与边界数据曾为零；DOM 测量应针对渲染就绪的可见页并与截图交叉确认，而不是一概认定 DOM 不可用。

旧环境还记录过 `--headless=new` 无法写出截图。该失败只属于当时的浏览器与调用环境，不应作为永久命令规则。选择当前可用的浏览器自动化或导出方式，不能只依赖某台机器的私有缓存。

## 6. 导出与演示验证

Slidev 的 CLI 导出需要可用的浏览器依赖。按当前版本要求准备 `playwright-chromium` 及浏览器；也可用当前 CLI 支持的路径参数指定已有浏览器，但不能因此省略 CLI 所需的软件包。仅安装软件包不等于浏览器已就绪。安装依赖属于单独的工程变更。

以下为使用当前入口的命令示例，本轮未执行：

```bash
pnpm exec slidev export ch00.md --format pdf
pnpm exec slidev export ch00.md --format png --range 1-3
pnpm exec slidev export ch00.md --with-clicks
```

按实际目标替换入口和范围；参数以安装版本的帮助为准。导出后打开产物核对内容，不以命令退出成功作为完整验收。

- `--with-clicks` 可保留点击步骤，但不保证滚动区域、iframe 或外部交互完整。
- PDF 中的滚动代码需要静态展开说明、补充页或可访问的完整源码；不能默默丢掉下半段。派生材料不成为另一份独立维护的源头。
- 现场演示应从约定初始状态启动，检查预期结果和复位。Web 场景还需核对请求/响应、加载态、错误态与恢复操作，不只看首页能打开。
- 外部服务、网络、iframe 或现场运行失败时，切换已核对的截图、录屏或模拟材料；明确标注模拟场景和限制。
- 无法完成检查时报告阻塞条件及未验证范围，不把历史记录、截图样例或构建成功当作本次验收证据。

## 7. 技术交付摘要

随本次修改简短回报：目标入口与单元范围、实际检查的页面与状态、示例执行和导出结果、必要证据位置、未验证项与替代材料。命令建议与实际运行结果分开写。

当前文档仅说明检查方法；统一截图、资源检查、代码测试等自动化入口尚需另行建设，不能向教师承诺已有一键检查。教学是否可交付仍按[通用流程](authoring-workflow.md)判断。
