# 教学课件制作流程

> **适用范围**：计算机软件类专业课程的概念讲授、代码讲解、项目演示、调试与实验教学。不限定课程、编程语言、目录命名或课件引擎。
> **目标**：教师定教学意图，AI 承担呈现、机械核对和工程维护；教师不必掌握排版语法。

## 1. 阅读路径与边界

| 读者 / 用途 | 文档 |
|---|---|
| 教师准备一次课 | [教学底稿编写指南](lesson-draft-guide.md) |
| AI 执行制作与维护 | 本文 + [Slidev 实施指南](slidev-authoring-guide.md) + [当前课程约定](course-conventions.md) |
| 查询旧设计及实测证据 | [改造前流程快照](history/authoring-workflow-legacy.md) |

本文规定通用流程；实施指南说明工具用法；课程约定补充教学环境、目录和视觉选择，不能覆盖本文的内容所有权、教师裁决权与真实性要求。旧版快照不作为现行规范。

迁移课程时复用流程和适用的实施指南，改写课程约定即可；不要求建立多课程框架或新配置格式。

## 2. 核心原则

1. **意图用自然语言，结构保持宽容。** 底稿是教案，不是表单。不写解析底稿的转换器、schema 或校验器；不因格式或字段缺失退稿。禁止的是底稿 DSL，不是对最终课件、代码和资源做测试、构建、检查或导出讲义。
2. **宽容格式，不掩盖矛盾。** AI 主动审读；明确的机械问题修正并回报，教学取舍与事实冲突由教师裁决。缺素材可标注占位，不能编造来源或将模拟结果冒充实测。
3. **最终课件工程是唯一权威来源。** 正文与备注、可运行示例、资源各维护自己的权威源文件。底稿一次移交后归档；后续就地编辑最终工程，不回写底稿、不用旧底稿覆盖整份成稿。
4. **可运行教学示例具有独立来源。** 使用独立源文件，或可定位版本的外部项目；课件引用或展示必要片段。独立来源不等于必须单文件、必须编译或放在某个固定目录。
5. **内容详实，优先教学价值与制作美观。** 以准确性、解释力、完整性及高信息密度下的可读性评价课件；不默认追求极简、减少总页数或增加师生互动。分页、动画与图示服务讲解，不为凑版面删教学内容或任意切断上下文；必要时增加承接页。

## 3. 分工与写作单位

| 事项 | 教师 | AI |
|---|---|---|
| 目标、深度、顺序、练习和取舍 | 决定；对不确定处作裁决 | 提出矛盾、缺口及建议，不擅自删改 |
| 讲述、提问、停顿、操作意图 | 提供逐字稿或口语提纲均可 | 分配到正文、备注和演示步骤，保持原意 |
| 分页、样式、图示、交互 | 有教学原因时指定或否决 | 默认负责，给出简短方案 |
| 示例与素材 | 提供已有材料，确认教学要求 | 整理、按约定补充并验证，说明来源和未验证项 |
| 后续修改 | 用自然语言提出 | 定位影响范围、就地编辑并检查 |

通常一次交付完整一次课，AI 先理解全局，再分批制作。**写作单位是教学单元，不是页**：可以是一个概念、问题、任务或实验。

单元超过约 10–15 分钟或 8–10 条要点时，提示教师考虑拆分；这是讲授的软提示，不是连续实验的硬上限。改变教学编排需教师确认，视觉分页归 AI。

AI 保留或补充稳定编号，并在成稿中留下可定位的对应关系；编号不随插页重排。教师可用编号、标题或内容描述提出修改，不必学习标记语法。

## 4. 制作步骤

**完整底稿 → AI 审读 → 分页方案与关键表达验样 → 同一工程内分批成稿 → 分层验收 → 授课反馈 → 就地维护**

### 审读：先处理会造成大返工的问题

AI 对照底稿核查数量、交叉引用、目标与内容覆盖、时间预算、来源、素材和演示条件，给出简短结果：

- **直接处理**：答案唯一的机械问题，如表格计数或明显重复，修正后回报。
- **教师裁决**：定义口径冲突、事实真伪未定、重要内容取舍、教学顺序变化；不靠猜测定稿。仅阻塞相关部分，其他明确内容可继续。
- **带占位继续**：缺失截图、待补实测数据等；说明缺口与替代方式，不静默跳过。

AI 整理已有信息，只追问影响正确性或制作方向的缺口，不要求教师补齐表格。

审读采用以下内容质量基线，不要求每页重复同一套结构：

- **主线闭环**：标题与目标承诺的内容有落点；概念通过实例得到解释，涉及实现的单元能贯通规格、接口、实现、调用与结果。先备知识讲完后回到原问题，不让工具回顾取代主线。
- **结论有理由和边界**：关键结论配解释或证据，注明必要前提；区分语言 / 协议保证、课程约定、简化模型与特定环境中的观察。复杂度、性能倍数、资源大小等说明比较口径，不把一次实测泛化为保证。
- **语义而非名词罗列**：接口说明输入、输出或状态变化及必要前置条件；代表性实例优先复用已有资产，代码、图、输出解释同一行为，避免频繁更换案例。
- **课后可读**：关键定义、推理、结论、必要条件及例题解析在课件正文或明确链接的配套材料中可找到；备注主要承载口语展开、节奏和操作提醒，不能成为核心知识的唯一载体。
- **前后可核对**：术语与符号一致，前文承诺后文兑现；清理失效节号、未讲过的回顾和过时备注。有疑问的规则先查当前环境与可信资料，必要时用最小示例验证并说明证据边界。

### 验样：确认关键表达，不逐页审批

先回报“教学单元 → 预计页面 / 演示”的简短对应关系，说明主线、需要拆开的原因和关键讲解步骤；有必要的互动才单独说明。

优先完成最不确定、返工成本最高的图示或演示，请教师确认教学表达。成熟常规页直接推进，不必等逐页批准。可从概念配实例、双图对照、代码配状态变化、证据截图、密集速查表中选择代表页验样；具体视觉标准见实施指南。

重点投入可以是一张图、一个实例或一次调试；不规定高光表达或互动数量。逐步显示首先服务教师解释顺序，不自动加入预测、投票或讨论环节。

### 成稿：一次移交，分批完成

**开始落地最终工程时，冻结底稿并标注“已归档 / 不再更新 / 以最终课件工程为准”及成稿位置。** 若验样已写入最终工程，此时即完成移交；后续批次仍可读取该快照。

归档不表示已经验收完成。后续反馈和补充材料只进入最终工程；允许在授权范围内重做局部表达，但不从归档底稿重新覆盖整份课件。

同一工程内按教学单元分批补齐正文、备注、示例与资源，持续维护来源对应；批次不成为需要教师维护的第二份教案。

## 5. 示例与演示资产

| 材料 | 处理边界 |
|---|---|
| 可运行示例 | 保留独立来源，包含运行所需的代码、配置、SQL 脚本、测试或演示数据；可以是单文件或多文件工程 |
| 外部项目 | 标明仓库位置、文件及可定位的提交或发布版本，不能只依赖会变化的默认分支 |
| 伪代码、短说明片段、演变动画 | 可内联；简化展示需说明省略范围，并与完整实现核对 |
| 故意出错的示例 | 可执行的错误示例也应保留独立来源，标明预期失败；无法执行的说明片段可内联 |
| 多个教学阶段 | 可以有起始版、故障版、修复版；明确各自用途及与最终实现的关系，避免无意重复维护 |

单个连续算法可留在同页滚动讲解；多文件协作、请求链路或调试过程可按阶段分页，通过文件身份、流程位置和必要回顾保持上下文。

演示按需要说明运行环境与依赖版本、启动和检查方法、初始数据、复位方法、网络依赖与失败备用方案。使用隔离数据，不依赖生产系统；不将真实凭据写进课件或示例。

故障演示的备用材料应是已核对的诊断输出、截图或录屏。对未定义行为、竞态或其他不稳定失败，说明诊断工具与触发条件；不能把偶然崩溃当作必然结果，也不以撤掉检测工具、反复试跑碰结果作为备用方案。

## 6. 分层验收与交付

验收对象是**实际要讲的内容和交付形态**。先确认目标次课进入了验证入口，不能以其他页面或整站构建成功代替目标内容检查。

| 层次 | 检查重点 |
|---|---|
| 内容 | 对照审读基线检查主线闭环、结论前提与课后可读性；必讲点和约定的例题解析不遗漏，正文、备注、源码、图和结果一致 |
| 技术 | 构建与资源引用有效；示例按其类型检查结果、接口响应、浏览器状态、数据变化或预期失败，不只看能否编译 |
| 视觉 | 信息层级、对齐、字号与对比度；代码、图中标签和截图证据可读，末行与底部总结完整；截图及边界检测只是辅助证据 |
| 授课 | 关键点击、备注及操作顺序匹配；仅在设计了预测或提问时检查答案揭示顺序；演示可复位、可在限定时间内切换备用材料 |

简单静态页检查初始与最终状态；动画、代码演变和交互重点页检查关键中间状态。等待内容实际就绪，不能把空白截图当通过。

网页与静态 PDF 分别验收。依赖滚动、动画或现场操作的部分，需要可读的静态说明或替代材料；网页通过不代表 PDF 完整。

交付时用简短说明列出：

- 本次覆盖的教学单元、对应页面或演示，以及相对底稿的重要内容差异。
- 实际检查的入口、范围、环境、结果和必要证据；未执行的检查明确写“未验证”。
- 遗留占位、阻塞问题及备用方案。重要正确性问题未解决时不能标成可授课；教师可确认带明确替代方案的有限交付。

说明不复制教学正文，也不要求教师维护新的状态表。**规范要求执行检查，不意味着仓库已经具备自动检查工具。**

## 7. 就地维护与课后反馈

每次修改先定位影响范围，再做最小必要修改并验证：

| 修改对象 | 至少检查 |
|---|---|
| 正文、图示或备注 | 当前页及直接关联的定义、条件、实例解析、数量、备注和前后承诺 |
| 删除或移动教学单元 | 目录、练习、前后呼应、跨课引用和稳定编号 |
| 代码、数据或交互步骤 | 所有引用页、演变片段、行高亮、预期结果及相关状态 |
| 公共组件、主题或全局样式 | 使用它们的章节或模块，扩大视觉回归范围 |

完成一章或一个教学模块后，按实际版式样册做一致性体检：归一同类页样式、收敛临时实现，不擅自改教学内容。

版式库保障下限，不限制表达：从实际页面归纳，同类表达第二次使用后登记为参考，稳定复用三次以上再考虑组件化。先复用样例，不预设完整组件体系。

课后教师只需反馈三件事：哪里超时、哪里暴露理解困难、哪里呈现妨碍讲解。AI 将反馈转为最终工程的局部修改。

新学期备课从最新工程提取内容；归档底稿只作历史参考，不默认仍是准确教案。导出的讲义或提纲是派生产物，不作为另一份同步维护的源头。

## 8. 验证状态与持续改进

历史实测结论仅适用于记录中的课程、版本与环境；详见[旧版快照](history/authoring-workflow-legacy.md)。不能据此宣称所有课程或新版本均已验证。

审读、关键表达验样、分层验收及跨课程适用性的效果仍需课堂实测。内容质量与视觉标准可从实际课件分析中提炼，但规范更新不等于已有课件完成修正或通过验收。下一次试验记录教师实际投入时间和返工原因，并结合课堂反馈判断效果；不先建立复杂指标体系。

迁移验收至少走读两种场景：单文件代码讲解、多文件协作与界面演示。两者都应只需补充课程约定和运行条件，而不必修改这套通用流程。
